# Ускорение расшифровки уроков — волна 2, инкремент 1 (2026‑11‑20)

Ветка `transcription-speedup-v2`. Движок расшифровки на Mac учителя
(`tools/local-transcription`). Всё новое — **за флагами, по умолчанию выключено**:
без переменных окружения модуль ведёт себя ровно как раньше (проверено — весь
набор python‑тестов и `check:ui` зелёные, формат `segments.json` в дефолте не
меняется).

> Примечание. В задаче упоминался файл `docs/analysis/video-transcription-2026-11-17.md`
> — его в репозитории (ни в `main`, ни в истории) нет. Работал по актуальному
> коду `origin/main`: конвейер за 777 коммитов ушёл вперёд от ветки‑заготовки,
> поэтому ветку пересоздал от свежего `origin/main`.

## Что в этом PR (за флагами)

| Флаг | Значение по умолчанию | Что делает |
|---|---|---|
| `ISKRA_ASR_ENGINE` | `whisper` | `gigaam` — GigaAM v3 e2e‑CTC для русской речи (**с пунктуацией**); `auto` — русский монолог → GigaAM, смешанная речь → whisper |
| `ISKRA_VAD_SEGMENT` | выкл | `1` — резать аудио на куски по паузам (Silero VAD), а не ровно по 90 с |
| `ISKRA_WORD_TIMESTAMPS` | выкл | `1` — добавить пословные таймкоды (поле `words` у реплики, аддитивно) |

Пути к моделям переопределяются: `ISKRA_ASR_ASSETS`, `ISKRA_GIGAAM_MODEL`,
`ISKRA_GIGAAM_TOKENS`, `ISKRA_VAD_MODEL`. Модели качаются по требованию только
если флаг включён (`model_cache.ensure_asr_assets`), иначе не трогаются.

### 1. GigaAM как альтернативный движок (русский монолог)
- `sherpa-onnx` уже стоит (используется для разделения голосов). GigaAM
  подключается через `OfflineRecognizer.from_nemo_ctc`.
- **Рекомендуемая модель — GigaAM v3 e2e‑CTC** (`gigaam_v3_e2e_ctc_int8.onnx` +
  `gigaam_v3_e2e_ctc_tokens.txt`, ~320 МБ). В отличие от char‑CTC v2, это BPE‑модель
  (256 токенов): текст выходит **с пунктуацией и заглавными**. На тест‑клипе RU дала
  практически эталон («Сегодня на уроке мы разберём строение клетки. Клетка состоит
  из ядра, цитоплазмы и мембраны…»), WER 0 %. Это снимает главный минус GigaAM и
  делает движок пригодным для читаемого конспекта.
- **Источник и лицензия.** Официальных v3 в релизах k2‑fsa пока нет; берём с зеркала
  `Smirnov75/GigaAM-v3-sherpa-onnx` на HF — **лицензия MIT** (как и upstream
  salute‑developers). ⚠️ Это сторонний релиз: для продакшена операторy стоит
  перезалить две нужные модели на свой R2/зеркало (как уже сделано с ffmpeg),
  чтобы не зависеть от чужого HF‑репозитория. Качаются по требованию только две
  нужные модели, не весь ~5 ГБ репозиторий.
- **Загрузчик один — `from_nemo_ctc`** — поэтому на свой путь
  (`ISKRA_GIGAAM_MODEL`/`TOKENS`) можно поставить и официальный v2 k2‑fsa (MIT),
  и v3‑plain (строчный). ⚠️ **RNN‑T‑экспорты (encoder/decoder/joint) не грузятся** —
  для них нужен `from_transducer`, это следующий инкремент.
- Токены у разных моделей разные (v2 — 33 символа, v3 e2e — 256 BPE), поэтому при
  своём пути задавать нужно **и модель, и токены**.
- Маршрутизация `auto`: по первому куску пробуем язык через whisper; если язык ≠ ru,
  либо в тексте есть корейский/японский/иероглифы, либо много латиницы (≥12 % букв)
  — весь урок идёт на whisper. Иначе — на GigaAM. (На смеси RU+EN даже v3 e2e даёт
  ~27 % WER против 0 % у whisper — поэтому маршрутизация нужна.)
- Словарь исправлений (`terms.json`) к GigaAM тоже применяется.

### 2. Резка по паузам (Silero VAD) вместо жёстких 90 с
- Раньше ffmpeg резал ровно по 90 с — граница могла попасть на середину слова.
  Теперь (при флаге) декодируем всё в один wav, Silero VAD находит речь, а границы
  кусков ставятся **в тишину** рядом с ~90 с.
- **Инвариант конвейера сохранён:** куски идут подряд и покрывают всю запись без
  пропусков и без перекрытий (это важно для `recognize.py` offset, `silence.py`
  волны и `diarize.py` склейки дорожки). Перекрытие НЕ делаю намеренно: раз граница
  в тишине, рвать на стыке уже нечего, а перекрытие сломало бы тайминг и удвоило бы
  тишину в форме волны. Проверено на 240‑секундном файле: 3 куска (88.9/85.6/65.2 с),
  суммарное покрытие точно совпадает с длительностью.
- Нет sherpa/модели silero → тихий откат на прежнюю резку по 90 с, задание не падает.

### 3. Пословные таймкоды
- whisper: `word_timestamps=True`, у реплики появляется поле `words`
  (`[{word,start,end}]`), сдвинутое в абсолютное время записи.
- GigaAM: слова собираются из таймкодов токенов. Работает и для char‑CTC (v2/v3‑plain,
  пробел — отдельный токен), и для BPE (v3 e2e, пробел зашит в токен `' С'` → начало
  слова). Текст реплики в обоих случаях корректный.
- Поле **аддитивное**: при выключенном флаге его нет, формат `transcript` не меняется.
  Караоке‑подсветка в плеере — это волна 3, здесь только данные.

## Границы
Основное — конвейер расшифровки (`tools/local-transcription`) + регенерация версии
модуля (`src/lib/transcriptionModuleVersion.ts`, `transcriptionInstallerVersion.ts`
— автогенерятся сборщиком). Плеер, кабинет ученика, итоги урока (lesson‑recap) и
формат `lessons.content.transcript` не трогал; новые поля — только аддитивно.

**Исключение (по прямой просьбе Дани):** добавлен тумблер «Быстрое распознавание
(эксперимент)» в окне расшифровки преподавателя
(`src/components/teacher/LocalTranscription.tsx`, режим «По тексту»). Это выходит
за первоначальную рамку оператора «только env, UI не трогать», но нужно, чтобы
препод мог тестировать без env‑переменных. Тумблер по умолчанию **выключен**
(поведение по умолчанию прежнее), шлёт заданию `engine=auto`; сервер (`server.py`)
читает поле `engine` на задание и перекрывает им env только для этого задания.
Строки — русские, как и весь этот компонент (он не i18n‑зирован). Студенческий
UI, плеер и формат расшифровки по‑прежнему не затронуты.

## Замеры

⚠️ **Честно: настоящий WER на реальных уроках я измерить не мог** — у меня нет
записей Дани и, главное, нет эталонных текстов (WER без эталона не считается). Ниже
— то, что удалось получить локально на синтетике (TTS Milena) и на реальном
тест‑сэмпле GigaAM. Для настоящих цифр в PR добавлен harness `benchmark.py`
(см. ниже) — его нужно прогнать на 3–5 своих уроках.

### Синтетические клипы (TTS, короткие — скорость искажена прогревом моделей)
`gigaam-v2` — char‑CTC (строчный), `gigaam-v3` — e2e‑CTC (рекомендуемый, с пунктуацией).

| клип | движок | ×реал.вр. | WER (норм.), % |
|---|---|---|---|
| RU монолог (11 с) | whisper | 1.98 | 4.5 |
| RU монолог (11 с) | gigaam‑v2 | 5.25 | 4.5 |
| RU монолог (11 с) | **gigaam‑v3 e2e** | 2.65 | **0.0** |
| RU+EN смесь (8 с) | whisper | 2.61 | **0.0** |
| RU+EN смесь (8 с) | gigaam‑v2 | 4.29 | 40.0 |
| RU+EN смесь (8 с) | gigaam‑v3 e2e | 3.59 | 26.7 |

WER считается по нормализованному тексту (без регистра и пунктуации), поэтому главный
плюс v3 e2e — **сама пунктуация и заглавные** — в этих числах не виден, но в тексте
есть: v3 e2e выдала «Сегодня на уроке мы разберём строение клетки. Клетка состоит из
ядра, цитоплазмы и мембраны…».

Выводы:
- на **чистом русском** GigaAM не хуже whisper по WER, а v3 e2e ещё и с пунктуацией;
- на **смеси RU+EN** любой GigaAM хуже whisper (v2 40 %, v3 e2e 27 % против 0 %) —
  отсюда маршрутизация «смесь → whisper»;
- ×реал.вр. на 8–11‑секундных клипах занижен (почти всё время — загрузка модели);
  v3 крупнее v2, поэтому на микро‑клипах его ×реал.вр. ниже — нужен замер на
  реальном уроке, где загрузка амортизируется.

### Амортизированный прогон (240 с, прогрев размазан)
Тестовый файл — 20× склейка русского клипа с паузами (речь настоящая, но
повторяющаяся — это проверка скорости, не содержания). Прогоны шли под фоновой
нагрузкой (`check:ui`), поэтому абсолютный ×реал.вр. шумноват — **надёжен
относительный разрыв между движками**, а не точное число.

| резка | движок | кусков | время, с | ×реал.вр. | WER, % |
|---|---|---|---|---|---|
| fixed | whisper | 3 | 93.0 | 2.58 | 4.8 |
| fixed | **gigaam** | 3 | 19.6 | **12.26** | 5.5 |
| vad | whisper | 3 | 175.7 | 1.36 | 4.5 |
| vad | gigaam | 3 | 44.0 | 5.45 | 5.0 |

- **GigaAM стабильно в ~5 раз быстрее whisper** при сопоставимом WER (разница ~1 п.п.).
  Это главный сигнал ради скорости.
- Разброс whisper fixed↔vad (2.58 vs 1.36) — шум от фоновой нагрузки, не эффект VAD.
  **VAD — это про корректность** (не рвать слова на стыках), а не про скорость;
  декодирование в один wav + инференс VAD даже добавляют немного работы. Так что
  включать VAD имеет смысл ради качества стыков, а ускорение брать от GigaAM.

### Как мерить на своих уроках
```
cd tools/local-transcription
python benchmark.py урок1.mp4 урок2.m4a --engines whisper,gigaam --seg fixed,vad --ref ПАПКА_С_ЭТАЛОНАМИ
```
Эталон для `урок1.mp4` — файл `урок1.txt` рядом или в `--ref`. Без эталона считается
только скорость. WER — по нормализованному тексту (нижний регистр, без пунктуации),
чтобы whisper и беспунктуационный GigaAM сравнивались честно. Harness ничего не
публикует в Искру — только гоняет локальные модели и печатает таблицу.

### Заливка моделей v3 на R2 (чтобы не зависеть от чужого HF)
Нужны два файла (их же использует модуль): `gigaam_v3_e2e_ctc_int8.onnx` (~320 МБ)
и `gigaam_v3_e2e_ctc_tokens.txt`. Скачать с зеркала и залить в свой бакет:
```
# скачать два файла
python - <<'PY'
from huggingface_hub import hf_hub_download
for f in ("gigaam_v3_e2e_ctc_int8.onnx","gigaam_v3_e2e_ctc_tokens.txt"):
    print(hf_hub_download(repo_id="Smirnov75/GigaAM-v3-sherpa-onnx", filename=f, local_dir="gigaam-v3"))
PY
# залить в R2 (пример для rclone/aws cli — под свой бакет и публичный префикс)
aws s3 cp gigaam-v3/gigaam_v3_e2e_ctc_int8.onnx   s3://<bucket>/models/gigaam-v3/ --endpoint-url <R2_endpoint>
aws s3 cp gigaam-v3/gigaam_v3_e2e_ctc_tokens.txt  s3://<bucket>/models/gigaam-v3/ --endpoint-url <R2_endpoint>
```
Затем в окружении модуля (или в `start.command`) задать базовый URL без имён файлов:
`export ISKRA_GIGAAM_URL_BASE=https://<публичный-домен-R2>/models/gigaam-v3`.
Модуль скачает `<base>/gigaam_v3_e2e_ctc_int8.onnx` и `…_tokens.txt`.
- **RNN‑T‑вариант GigaAM** (`from_transducer`) — если захочется сравнить с CTC;
  сейчас загрузчик только CTC.
- **Караоке‑подсветка слова в плеере** — волна 3 (данные `words` уже готовит этот PR).
- **Прогрев/переиспользование процесса** recognize между кусками (сейчас модель
  грузится в одном процессе на всю запись — ок; межзадачного кэша нет).

> Пунктуация GigaAM — ✅ сделано: дефолт переведён на v3 e2e‑CTC (с пунктуацией и
> заглавными), поэтому прежний минус «строчный без пунктуации» снят.

## §0. ЖЕЛЕЗНЫЕ ПРАВИЛА — не сломать ПК

Нарушение любого = регрессия десктопа. Проверять на каждом коммите.

1. **Никакого общего CSS, ломающего ПК.** Новые правила в `index.css` допускаются ТОЛЬКО
   внутри `@media (max-width: 1023px)` или под новым классом, который десктоп не использует.
   Существующие токены/классы НЕ переопределяем.
2. **Desktop JSX не трогаем.** Разветвление строго `isDesktop ? <старое> : <новое>`.
   Старая ветка остаётся байт-в-байт.
3. **Новые мобильные компоненты не импортируются десктопным кодом.** `Mobile*`-компоненты
   живут отдельно; десктоп их не видит.
4. **Общие токены (CSS-переменные, `theme.ts`, `feedback.ts`) меняем только аддитивно.**
   Удаление/переименование переменной = потенциальная поломка ПК. Дедупликация делается
   через новый слой, старое остаётся работать до явного аудита использования.
5. **Брейкпоинт один: 1024px.** `useIsDesktop()` (`window.innerWidth >= 1024`).
   Не вводим новые брейкпоинты без причины.

**Контроль:** после каждой задачи — `npm run build` (типы) + визуальная проверка ПК
в превью (десктоп-ширина) + мобайл (375/390px).

## §1. ПРИНЦИПЫ ПРОЕКТИРОВАНИЯ МОБАЙЛА

### 1.1. Layout-модель iPhone (УТВЕРЖДЕНО)
```
┌─────────────────────────────┐
│  ВЕРХ: виджет/контекст       │ ← плавающий glass, scroll-under + фейд
│  · · · · · · · · · · · · · · │
│         КОНТЕНТ              │ ← скроллится ПОД верхним виджетом
│  (один экран, мин. скролл)   │
│  · · · · · · · · · · · · · · │
│  НИЗ: контролы страницы      │ ← фильтры/сортировки в стеклянных кругах
│  НИЗ: навигация (4 вкладки)  │ ← MobileBottomNav, 44px от края + safe-area
└─────────────────────────────┘
```
- **Safe-area везде.** `env(safe-area-inset-*)`. Низ — обязателен (home-indicator),
  верх — для notch/Dynamic Island.
- **Низ = зона большого пальца:** навигация (4 вкладки) **И** контролы текущей страницы
  (фильтры/сортировки/поиск-триггер) — в стеклянных кругах с иконками. Нижний блок отстоит
  **44px** от края экрана (поверх safe-area).
- **Верх = контекст:** плавающий стеклянный виджет/привет. Контент уходит под него
  (scroll-under + фейд), верх не перекрывает контент жёстко.
- **Правило одного экрана.** Стремимся уместить в один экран без скролла. Скролл — только
  там, где контента физически больше экрана (списки уроков/задач, конспект). Управляющие
  элементы скролл НЕ вызывают — они закреплены снизу.

### 1.2. Панели управления (фильтры/сортировки)
- Фильтры/сортировки — в **стеклянных кругах** (glass pill/circle) с **иконкой-объяснением**
  что это (Filter, ArrowUpDown, Search…).
- Размещение — сверху или снизу, что органичнее для конкретной страницы (обосновать в задаче).
- Раскрытие — bottom-sheet или inline-expand, НЕ обрезается контейнером.

### 1.3. Скролл-дисциплина (критично)
- **Нет горизонтального скролла страницы.** Любой горизонтальный скролл — только намеренные
  карусели/ряды чипсов с `overflow-x` и скрытым скроллбаром.
- **Скроллбары прячем** (`.no-scrollbar`) там, где есть фейды.
- **Overscroll контейнеров** — `overscroll-behavior: contain`, чтобы не тянуло body.
- **Граница body сверху/снизу** — не допускаем «резинку» всего экрана там, где скроллится
  внутренний контейнер.
- **Фейды на ВСЕХ скроллах** — горизонтальных (карусели, ряды чипсов, поля) и вертикальных
  (списки, дропдауны). Используем `ScrollFade` (верт.) и `.horizontal-fade`/маски (гориз.).
  Фейд появляется только если есть скрытый контент за краем.

### 1.4. Границы контейнеров — не обрезать эффекты
- Тени, свечения (glow), обводки (ring), liquid-glass-блики **не должны клиппиться** родителем.
- Если у элемента есть `box-shadow`/`filter`/outline — родитель не ставит `overflow: hidden`
  без запаса `padding`/`margin` под эффект.
- Карусели с тенями карточек: контейнер с `overflow-x` должен иметь вертикальный запас
  (padding top/bottom), чтобы тень не срезалась.
- Текстовые поля и дропдауны — стеклянные, раскрытие не обрезается (рендер во внешнем слое
  или достаточный паддинг/нет `overflow:hidden`).

### 1.5. Тактильность (желе, хаптика, звук)
Используем СУЩЕСТВУЮЩИЕ примитивы (`lib/feedback.ts`), не плодим новые:
- **Хаптика:** `haptic(pattern)` (Vibration API). Лёгкий тап — `10`, lock — `[7,3,4]`,
  release — `[4,2]`. Каждое значимое нажатие/переключение — отдаёт вибрацию.
- **Звук:** `blip()`, `tactile()`, `lockSnap()`, `lockRelease()`. Тап = `tactile()`.
- **Желе-анимации:** spring `cubic-bezier(0.34, 1.46, 0.64, 1)` (как `topbar-snap`).
  Нажатие — `whileTap={{ scale: 0.9..0.97 }}`. Появление — spring с лёгким overshoot.
- **Имитация веса/отягощения:** при скролле/докинге — «сопротивление → щелчок»
  (`springTopbar`, jelly-keyframes). Тяжёлые элементы пружинят с большей амплитудой/инерцией.

## §2. TDS — Token Design System (свет + тьма)

> Цель: единый каталог токенов и пар «фон↔текст». Все мобильные компоненты берут цвет
> ТОЛЬКО отсюда. Новые цвета добавляем сюда, не хардкодим hex в компонентах.

### 2.1. Базовые поверхности (`index.css`, уже есть)
| Токен | Light | Dark | Назначение |
|---|---|---|---|
| `--color-bg` | `#F5F5F6` | `#111113` | фон страницы |
| `--color-bg-2..5` | светлые | тёмные | вложенные поверхности |
| `--color-bg-input` | `#fff` | `#202022` | поля ввода |
| `--glass-rgb` | `255,255,255` | `22,22,24` | база стекла (`rgba(var(--glass-rgb), α)`) |
| `--color-surface` | `rgba(255,255,255,.92)` | `rgba(22,22,24,.92)` | непрозрачная карточка |

### 2.2. Текст
`--color-text` → `-2` → `--color-muted` → `-3` → `-4` → `-5` (убывающий контраст).

### 2.3. Границы
`--color-border` / `-soft` / `-medium` / `-strong` / `--color-border-glass`.

### 2.4. Тени (одна шкала, авто-адаптация по теме)
`--shadow-xs/sm/md/lg`, `--shadow-pill`, `--shadow-bar`, `--shadow-dropdown`,
`--shadow-filter`, `--shadow-modal*`. **Не пишем box-shadow руками — берём токен.**

### 2.5. Цветовые ПАРЫ (фон-soft ↔ текст-on-soft) — КАНОН
Это раздел против дублей: на каждый смысловой цвет — **ровно одна** пара. Любой чип
обязан использовать пару отсюда.

| Смысл | Фон (soft) | Текст | Источник |
|---|---|---|---|
| Успех/выполнено | `--color-green-soft` | `--color-green-text` | status: completed |
| Возврат/warning | `--color-yellow-soft` | `--color-yellow-text` | status: returned |
| Ошибка/не сдано | `--color-red-soft` | `--color-red-text` | status: unviewed |
| В проверке | `--color-peach-soft` | `--color-peach-text` | status: submitted |
| Текущее/фокус | `--color-purple-soft` | `--color-purple-text` | PURPLE (today/current) |
| Инфо | `--color-blue-pill-bg` | `--color-blue-pill-text` | инфо-чипы |
| Доп. акцент | `--color-teal-pill-bg` | `--color-teal-pill-text` | вторичные метки |
| Розовый | `--color-rose-soft` | `--color-rose-text` | спец. метки |

**Предметные пары** — `theme.ts` → `subjectTheme(subject, dark)` → `{text, soft, accent, onAccent, ring}`.
Биология = зелёная, Химия = фиолетовая. Бренд-фиолетовый (`PURPLE`) = «сейчас/сегодня»,
НЕ предмет.

### 2.6. Кнопки — канон вариантов (против дублей кнопок)
Сводим все кнопки к **4 вариантам**. Любая новая кнопка — один из них.

| Вариант | Фон | Текст | Тень | Применение |
|---|---|---|---|---|
| `primary` | `--color-accent` | `#fff` (onAccent) | `--shadow-md` | главный CTA |
| `glass` | `rgba(var(--glass-rgb),.72)` + blur | `--color-text` | `--shadow-xs` | вторичные, табы-актив |
| `ghost` | transparent | `--color-text`/muted | none | неактивные табы, текст-кнопки |
| `soft` | пара-soft из §2.5 | пара-text | none/`--shadow-xs` | статусные/предметные |

Активная пилюля-таб: фон `rgba(var(--glass-rgb),.72)` + blur + `--shadow-xs` +
`1px var(--color-border-glass)`. Неактивная: `ghost`. (Канон из `SubjectTabs`.)

### 2.7. Радиусы / отступы
`--radius-card:24` `--radius-large:32` `--radius-pill:999`. Стеклянный круг-фильтр —
`999`. Карточки — `24`. Bottom-sheet — `32` сверху.

## §3. ЧИСТКА ДУБЛЕЙ (аудит)

Найденные дубли/расхождения для устранения (аддитивно, без поломки ПК):

- **D1 — Два звуковых движка.** `lib/sound.ts` (`playClick/playPop/playUnlock/`
  `playTransitionDrop/vibrate`) и `lib/feedback.ts` (`blip/tactile/haptic/lockSnap/`
  `lockRelease`) — оба держат свой `AudioContext`. Канон → `feedback.ts`. `sound.ts`
  обернуть/пометить deprecated, мобайл использует только `feedback.ts`. (НЕ удалять
  `sound.ts` пока на нём висит десктоп — §0.4.)
- **D2 — Чипсы/пилюли копипастятся** инлайном (`SubjectTabs`, фильтры `TaskBankPage`,
  табы курсов). Один и тот же стеклянный pill переизобретается. → Завести `MobilePill`
  (только для мобайла) на канон-стилях §2.6.
- **D3 — Хаптика-вызовы** идут то через `sound.vibrate`, то через `feedback.haptic`. → мобайл
  только `feedback.haptic`.
- **D4 — Статус-палитры** дублируются: `cardStyle` в `CoursesPage`, `TRACK_STATUS` в `theme.ts`,
  инлайны в `LessonStatusCard`. → канон `TRACK_STATUS` + пары §2.5.

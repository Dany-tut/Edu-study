# Переходы к курсу и запись из карточки расписания

База проверки — 5d377494. Входы с домашней работы, локальной очереди транскрипций и расписания сходятся в редакторе курса. Каталог открывает сохранённый курс, локальный курс либо шаблон. Повторный вход и смена целевого урока должны привязать экран к новому контексту. Проверяем целевые UUID и короткие идентификаторы независимо, включая одинаковые названия, неоднозначный номер, исчезнувший урок, смену страницы во время запроса.

Для карточки расписания используем связанные строки фиктивного расписания и курса. Проверяем задержку чтения, пустой набор изменений, единственную правку описания, неизвестные поля файлов, сохранность второго варианта глав, устаревшую версию, ошибку и поздний ответ. Критерий приёмки — запрос содержит только поля редактируемого урока и сравнивает подтверждённую версию. При конфликте черновик остаётся во вкладке.

Запуск: `node scripts/checkCourseEntryRoutes.mjs`. Сценарии исполняют код навигации и обработчик публикации с контролируемыми ответами. Видимая раскладка, физические устройства и production не входят в этот локальный протокол.

## Черновик глав расшифровки

На версии 3ec1ba60 фактический компонент в Chromium показал пустой список вместо подтверждённых глав после восстановления старого переключения на ещё пустые слайды. Воспроизводится командой `PLAYWRIGHT_CHANNEL=chrome ISKRA_CHAPTER_BASELINE=3ec1ba60 node scripts/checkTranscriptionChapterRecovery.mjs` (ожидаемое падение). На исправленном коде та же команда без переменной baseline проходит. Проверены временный просмотр пустого режима, явное удаление последней главы с перезагрузкой, отказ и повтор записи, поздние серверные главы, старый ответ после новой правки, две ссылки, два файла при одинаковом пустом URL и новая серверная версия после сохранения черновика. Сценарии использовали локальные данные. Факт исчезновения строк в базе этот тест не устанавливает.

Дополнительно фактическая карточка расписания с тестовым HTTP-клиентом прошла переход A→B с поздним ответом A и одной правкой описания на четырёх ширинах Chromium (1440, 390, 1024, 412). Результат — один запрос к B с UUID, версией и новым описанием, исходные главы видны в поле. На физическом устройстве и в production этот тест не выполнялся.

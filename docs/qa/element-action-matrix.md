# Искра: поэлементная матрица проверки

Этот документ дополняет [проверку геометрии](interaction-geometry-checklist.md) и `docs/ui-rules.md`. Для каждого экрана перед приёмкой составлять полный инвентарь интерактивных элементов, включая иконки без подписи, поля, списки, вкладки, переключатели, пункты меню, закрытие, очистку и действия, появляющиеся после hover/раскрытия. Динамические строки, пустой/длинный список и скрытые брейкпоинтом действия проверять отдельно. Не объявлять «все кнопки проверены» по нескольким основным действиям.

## Обязательная запись

Одна строка результата — одно сочетание `element × action × state × viewport × theme × browser`. Для большого количества сочетаний использовать отдельные таблицы экрана, сохраняя этот формат:

| Поле | Содержание |
|---|---|
| element | Стабильный ID/роль/доступное имя, экран, роль пользователя |
| action | Клик, повтор, быстрый повтор, клавиатура, ввод, раскрытие, выбор соседнего, возврат |
| state | Пусто, обычные данные, длинные данные/счётчик, loading, disabled, ошибка, успех, отмена, поздний ответ |
| viewport | Полные ширина×высота, ориентация, масштаб, клавиатура; resize из предыдущего состояния |
| theme | Каждая реально поддерживаемая тема, включая светлую/тёмную; выбор из интерфейса и восстановление после F5 |
| browser | Браузер/версия, ОС, физическое устройство либо эмуляция |
| expected / actual | Результат действия, данные/переход/фокус; положение, шрифт/читаемость, цвета, фейды и движение |
| evidence | SHA/хеши, сценарий, снимок/видео/координаты кадров и серверная проверка по применимости |
| status | PASS, FAIL, NOT TESTED, BLOCKED или NOT APPLICABLE с конкретным обоснованием |

Не заполненная клетка считается NOT TESTED. Сводный PASS разрешён только для явно перечисленного множества сочетаний. Исходники, снимок, unit-тест, настоящий UI и физическое устройство — разные виды доказательств.

## Темы, шрифты и стандарты

В каждой теме проверять сочетания фона, поверхности, текста, акцента и статусов; обычное/hover/pressed/focus/disabled/selected состояние. Оценивать читаемость основного и второстепенного текста, плейсхолдера, ошибок и текста поверх цветной поверхности. Цвет не должен быть единственным носителем статуса. Проверять реальные вычисленные цвета/контраст, системный fallback и загрузку шрифта, размер/начертание/межстрочный интервал, длинные русские и английские подписи, видимость текста при фейде и масштабировании. Численные требования доступности и применимый стандарт фиксировать в отчёте; без измерения и проверки клавиатурой/screen reader не заявлять соответствие стандарту.

Сверять все пункты `docs/ui-rules.md`: ScrollFade у фактического overflow, текстовые фейды, читаемость мобильных полей и размер действий, понятные ошибки и сохранение черновика, Loop-иконки и Искра/Testly, геометрию оверлеев, плавность и каждый клик. Зелёный CI не заменяет эту работу.

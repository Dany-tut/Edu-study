# Повтор физического ДЗ после исправлений

Это рабочая последовательность обычных XCUI действий, а не PASS всей карточки R7. Реквизиты в runner передаются только secretKey aliases. QA backend должен оставаться доступным одним continuous bridge на всю цепочку: остановка между методами вызывала позднее опустошение каталога в R7.

1. Cold QA App → роль «Я ученик» (contains) → Email studentAEmail → eye «Показать пароль» → TextField «Пароль» studentAPassword → exact value bool → «Скрыть пароль» → optional Done → «Войти». Ждать кабинет, при consent нажать switch «Согласен(а) на обработку данных.» и «Принимаю и продолжаю».
2. «Дневник» → action «Задания» → scroll до Button CONTAINS titleA. Перед открытием проверить A, отсутствие B. Ответы TextView «Впиши слово или фразу…» и «Развёрнутый ответ…». Заполнить6 и answer1, exact assert. Done, cold/reopenA, verify draft. «Сдать домашку», wait confirmation, «Продолжить». Независимая серверная сверка exact owner/student/ref/attempt1, B0.
3. Нормальный student logout на финальном SHA должен реально завершить Auth. R7 этого НЕ сделал: применялся только диагностический обход через teacher profile awaited logout. Этот обход запрещено считать PASS. Новый teacherA UIlogin: та же eye-first последовательность, server actor verification до записи.
4. Tab «Журнал» → Button CONTAINS titleA → проверить studentNameA/titleA/answer1/attempt1. Review поля TextView «Комментарий» / TextField «Итоговый результат, %». Long prompt scroll. Ввести returnComment, ОБЯЗАТЕЛЬНО Done перед «Вернуть на доработку». Read-only exact server proof.
5. Teacher tab «Ещё» → reveal «Выйти из аккаунта» → «Выбрать роль» → studentA fresh UIlogin. Diary→Задания→A. Проверить returnComment/status; «Пройти заново» →6/answer2→Done→submit. Сверить один canonical progress, ровно2attempts, первая returned, новая submitted, B0.
6. Fresh teacherA после нормального logout → Journal→A. Проверить namesA/titleA/current answer2/attempt2. Score90/commentFinal → explicit Done → reveal «Принять работу» → read-only server completed90, same progress, attempt2, count2, B0.
7. Fresh studentA → Diary→Журнал работ. Native HTML Journal result action имеет тип XCUI Other и label «Зачтено · История попыток · <titleA>»; обычный tap открывает историю с попыткой1/returnComment и2/90/commentFinal. «Открыть работу» даёт disabled answer2 и result90; history collapsible button CONTAINS «История попыток Сдачи», затем «Ответы в этой попытке».
8. Fresh studentB реальным login → Diary/Задания → только titleB/МаркерB/пустые2ответа, no A/answer/comment tokens. Не сдавать B. TeacherB isolation, late-response, controlled-save failures и double tap требуют отдельного прогона; R7 их не доказывает.

Каждый переход сначала записывает motion, затем ждёт конкретный AX loaded marker, затем отдельный screenshot: первый screenshot сразу после tap несколько раз фиксировал skeleton, хотя последующий AX уже содержал данные. Skeleton PNG не является доказательством loaded UI. Все auth видео/AX приватны. UI не раскрывает UUID попыток: только номера/текст; exact UUID сопоставлены независимым server reader, не выданы за UI IDs.

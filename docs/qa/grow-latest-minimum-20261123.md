# GrowTextarea: актуальный минимум при изменении ширины

База: 2db9eab4 (3572). S3 — исправление и QA; S1 — интеграция/публикация.
Карточка до запуска: `~/.codex/iskra-qa/grow-latest-minimum-20261123/scenario.md`.

## Причина и результат

После minHeight=0 →120 текущее поле правильно получает высоту120. Но при
изменении ширины существующий ResizeObserver вызывает функцию из первого
render, где minHeight ещё0, и поле снова сжимается до40/45px. Результат зависит
от времени создания наблюдателя, а не от действующего свойства компонента.

Минимум теперь хранится в ref, обновляемом layout-effect до расчёта высоты.
Наблюдатель читает актуальный ref. Формула border-box/content-box из 12904f52
не менялась, новых observers/listeners нет. Value, onChange, шрифт, padding,
выделение, исходная геометрия и API компонента сохранены. Изменение высоты
относительно старого ошибочного результата после resize — намеренный результат:
поле соблюдает минимум, который уже запросил вызывающий экран.

## Постоянная регрессионная проверка

`node scripts/checkGrowMinimumBrowser.mjs`

Использует реальный GrowTextarea, FIELD, app CSS/Tailwind preflight и локальный
React state из `scripts/fixtures/growLatestMinimum.tsx`. Сервер только127.0.0.1,
внешняя сеть запрещена; server save/production/user data не используются.
Варианты запуска: ISKRA_BROWSER_ENGINE=webkit; для установленного Chrome —
ISKRA_BROWSER_CHANNEL=chrome. Для повторения исторического дефекта можно задать
ISKRA_GROW_BASELINE_REF=2db9eab4: guard собирает именно старый компонент, сохраняя
тот же независимый oracle высоты. Это ожидаемый FAIL, а не сбой текущего фикса.

Финальная сборка PASS: Chromium16 + WebKit16 сочетаний. Профили: ПК1440/1024,
iPhone320/390, iPad820/1194, Android412 и дополнительно PC1440/Arial × обе темы.
Робото в локальном прогоне задан через ISKRA_QA_FONT_ROBOTO; шрифт не добавлен
в продукт/репозиторий. WebKit27.2 и установленный Chrome работают headless
на macOS — это browser fixtures, не физические iPhone/iPad/Android.

| Сценарий | Проверенный результат |
|---|---|
| 0→120→40→180→0 без изменения текста | Текущий минимум применяется |
| Сужение/расширение панели после каждого шага | После ResizeObserver минимум сохраняется |
| Border-box и content-box | Нет внутреннего clipping, clientHeight ≥ scrollHeight с допуском округления1px |
| 1→4→1 строки | Рост/обратное уменьшение и value сохраняются |
| Быстрые160→80 + новая ширина | Применяется последний минимум80 |
| Выделение1…4 перед resize | Диапазон выделения и введённое остаются прежними |
| Изменение окна | Минимум/достаточная высота соблюдаются |

Отдельная проверка теста: старый компонент из2db9eab4 ожидаемо падает и в
Chromium, и в WebKit на независимом условии min120 после изменения панели:
style.height=40 вместо120. Текущий source проходит те же проверки.
TSC и check:ui PASS. Manifest обоих прогонов содержит базу и SHA256 точного
протестированного GrowTextarea; checksum совпадает с замороженным исходником.

Артефакты вне git: `~/.codex/iskra-qa/grow-latest-minimum-20261123/`:
`chromium/results.json`, `webkit/results.json`, manifest и32PNG;
`baseline-chromium.log`, `baseline-webkit.log`, `types.log`, `ui.log`.
Просмотр финальных PNG ограничен выбранными desktop/mobile состояниями;
плавность всего приложения и server E2E не приписываются этой проверке.

## Границы native-слоя

В этот коммит не входят экспериментальные шрифтовые lift-профили. Общие
FIELD/inline/CSS/unadorned inputs и симметричный NameEntry не сдвигались:
универсальные поправки давали разнонаправленные результаты в SF/Arial/Roboto
и WebKit/Chromium. Name0.04em ранее отклонён из-за caps/digits в WebKit/Arial.
FloatField — отдельный уже опубликованный3572. Исследовательские font candidates
сохранены только в приватных QA-артефактах, без неиспользуемых runtime helpers.

# Данные для приёмочных стендов

Пустой стенд или один одинаковый пример не подтверждает работу взаимодействия.
До приёмки изменённого сценария подготовить различимые данные для каждого
переключаемого дня, ученика, группы, модуля и вкладки. В проверке сверять ID или
содержимое выбранной сущности: одинаковое количество строк не доказывает выбор.

Обязательные наборы там, где применимы:

- Пусто, один элемент, несколько, переполнение с прокруткой.
- Короткие/длинные подписи, многозначные счётчики, разные статусы.
- Соседние сущности с одинаковым количеством строк и разным содержимым.
- Предыдущий/следующий период, граница месяца/года, возврат к текущему периоду.
- Загрузка, ошибка, повтор, смена выбора во время запроса, поздний ответ.
- Изменение данных в открытом окне и сохранение введённого после ошибки.

Проверки выбора должны падать при намеренном отключении фильтра/смены ID.
Проверять обычный, повторный, быстрый клик, клавиатуру и возврат. Использовать
матрицу размеров/тем из interaction-acceptance.md; фиксировать непокрытые клетки.
Стенд с подменёнными данными не подтверждает загрузку, RLS и сохранение в БД:
это отдельный сквозной сценарий с контролируемым тестовым аккаунтом.

Реализованный пример: `qa/calendar/` + `npm run check:calendar-browser`.
Наличие этого примера не означает приёмку остальных экранов приложения.

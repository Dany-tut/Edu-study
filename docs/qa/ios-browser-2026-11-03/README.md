# Искра — доступность браузеров iOS

3 ноября 2026. Проверена фактическая установка браузеров через devicectl на подключённом iPhone и через simctl listapps на симуляторе Iskra Teacher. Desktop Chromium не использован как замена iOS-браузерам.

| Среда | Safari | Chrome | Yandex Browser |
|---|---|---|---|
| Физический iPhone 17 Pro | Установлен, 27.2 | Не установлен | Установлен, 2610.4.504 |
| Iskra Teacher, iPhone 17 Pro Simulator | Установлен, 26.3 | Не установлен | Не установлен |

Идентификаторы: Safari — com.apple.mobilesafari; Chrome проверен также точным запросом com.google.chrome.ios; Yandex Browser — ru.yandex.mobile.search.

## Физический iPhone

Попытка подключения через штатный iPhone Mirroring завершилась сообщением: «iPhone используется. Чтобы подключиться к iPhone, заблокируйте его». Кнопка «Подключиться» была нажата один раз; состояние подтвердилось повторным AX-чтением. Поэтому Safari и Yandex Browser на физическом телефоне не пройдены. Блокировка/настройки телефона не менялись. Приложения не устанавливались.

## Safari на симуляторе: что выполнено

По указанию родителя использованы simctl openurl для тестового localhost и simctl io screenshot для evidence. Production не открывался.

1. Открыт http://127.0.0.1:5189/#/teacher. Safari запущен. Первый снимок застал чёрный загрузочный экран, следующий — системный first-run диалог «Выбор поисковой системы / Продолжить» и за ним сообщение Safari «На странице … повторно возникла проблема».
2. Затем открыт статический build http://127.0.0.1:24594/#/teacher/login. HTTP-сервер подтвердил GET /200. На новом снимке сообщение о повторной проблеме не видно, но системный first-run диалог остаётся поверх страницы; UI Искры за ним не показан.
3. Попытки штатного UI-доступа через CUA к DeviceHub стабильного Xcode и обычного Xcode завершились timeout примерно30–32с со сбросом kernel. Достоверно нажать системную кнопку Continue не удалось.

## Что НЕ засчитано

Ни один iOS-браузер не имеет PASS для полного прикладного сценария. Запуск процесса Safari и GET200 не равны подтверждению JS-отрисовки, клавиатуры, scroll/soft edge или действий ДЗ. Chrome недоступен в обеих средах; Yandex установлен только на физическом телефоне, UI которого недоступен до блокировки. Desktop Chrome, UA/device emulation и WKWebView не выдаются за эти браузеры.

Для продолжения требуется штатно завершить first-run Safari в симуляторе и восстановить управление его окном; для физического Safari/Yandex — заблокировать свободный iPhone и подключить Mirroring. После этого проверять вход, длинные формы, клавиатуру, прокрутку, soft edge и сохранение/повтор ДЗ в каждом реально установленном браузере.

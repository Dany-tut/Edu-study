# Искра — мобильный цикл проверки ДЗ, 3 ноября 2026

## Исправленные дефекты

- MobileHomeworkReview помечал опубликованный результат только id строки lesson_progress. Повторная сдача использует тот же id, поэтому новая попытка могла остаться в состоянии «Проверено». Идентичность теперь включает attemptId (для legacy — время сдачи). Черновики новой попытки остаются отдельными.
- В подтверждении использовался пересчитанный текущий процент. Теперь сохраняется фактически опубликованное значение вместе с вердиктом конкретной попытки.
- Исключение callback обновления очереди попадало в общий catch публикации и показывало «Не удалось сохранить» после успешной записи и удаления черновика. Сбой обновления очереди теперь не меняет уже подтверждённую публикацию на ошибку.
- При чтении связанного ДЗ могли одновременно вернуться hw-* и course-строки одного ученика. useHomeworkSubmissions оставляет новейшую сдачу ученика. Известная дата имеет приоритет перед неизвестной; при равных или обеих неизвестных сохраняется серверный порядок.

## Границы и результаты

| Граница | Результат |
|---|---|
| UI → изолированный адаптер публикации | Пройдено |
| Ошибка адаптера → значения и черновик сохранены | Пройдено |
| Перезагрузка → восстановление черновика | Пройдено |
| Повторная отправка → подтверждение 85% | Пройдено |
| Намеренная ошибка callback очереди после успеха | Подтверждение сохраняется, ложной ошибки публикации нет |
| Новая попытка при прежнем progress id | Состояние «На проверке», пустая форма |
| Возврат новой попытки | Адаптер получил новый expectedAttemptId, комментарий и verdict returned |
| Следующий ученик | Пустые собственные поля, предыдущий комментарий не переносится |
| Реальный API → локальная БД → ученик | Не проверено: localhost:54321 не слушает |
| Реальная публикация в production | Не выполнялась |
| Системная клавиатура и жесты на устройстве | Не проверены этим проходом |

Браузерный прогон выполнен на dev-mobile-review.html с синтетическими данными и локальным адаптером. Параметры последней отправки и дополнительные переключатели новой попытки/ошибки очереди доступны только на DEV-стенде. Это не полноценный E2E с базой. Скриншот next-student.png фиксирует следующего ученика с чистой формой после возврата повторной попытки первого.

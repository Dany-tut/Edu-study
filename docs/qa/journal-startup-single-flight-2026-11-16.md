## Production retest и устранение первопричины

- На production 1.0.3278 оператор повторил холодный вход шесть раз. Во всех шести случаях обнаружились два перекрывающихся RPC; один из шести входов занял 7.116 с, в остальных были statement timeout до 20 с. Следовательно, проверка только очереди startup helper была недостаточной и выпуск 3278 не закрыл дефект.
- Разбор кода показал, что `teacher-data` канал при первом `SUBSCRIBED` рассылает синтетический `SYNC` по таблицам. `useCourseJournal` воспринимал его как изменение данных и запускал `readFreshJournalSnapshot`, обходя startup cache. Теперь первичная синхронизация отличается от reconnect; загрузку на входе уже покрывает холодный snapshot, а reconnect и реальные события продолжают запускать обновление.
- Postgres production log зафиксировал отмену compact RPC `57014` в вызове `teacher_journal_task_sources_v2`, внутри `teacher_journal_snapshot_v3`. Компактная ветка дважды вычисляла один и тот же JSON-список на каждую домашнюю работу — для `basicTask` и `basicTasks`. Новая миграция материализует один результат на строку и извлекает первый элемент из него.
- Добавлен opt-in диагностический вывод инициатора, формы snapshot (`compact` / `complete`), исхода и длительности. Включение только в своей сессии браузера: `localStorage.setItem('iskra:journal-perf', '1')`; отключение: `localStorage.removeItem('iskra:journal-perf')`. Идентификатор учителя не логируется.
- Новая автоматическая регрессия проходит реальный orchestrator cold-entry: App prefetch → запрос полного снимка маршрутом → начальный Realtime SYNC. Она проверяет, что начальный SYNC не делает повторный RPC и что запросы не пересекаются; отдельно проверяет, что reconnect и настоящее изменение по-прежнему обновляют данные. PostgreSQL fixture проверяет compact/full ответы, маркеры источников и RLS после новой миграции.
- Повторная production-приёмка на точном новом SHA обязательна: шесть холодных входов в Edge, фактический порядок/форма RPC, первый ответ и открытие «Работ» без таймаутов. До неё исправление не считается принятым.
- Заключение отдельно по логике / fixture UI / E2E / движению / устройствам: логика должна пройти release checks; production E2E не пройден до проверки точного SHA.

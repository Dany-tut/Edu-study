# Фиксированная область сообщений «Под полями»

Карточка до запуска QA. Область: вход ученика/препода по паролю, восстановление, Apple/Google и код из письма преподавателя. Исполнитель/проверяющий: Codex. База рабочей копии 1d80bf3081f9ba4b518e5a91a6988c07568145ad + локальные изменения; точный hash-манифест будет сохранён перед проверкой. В папке есть незавершённые изменения других задач, они не относятся к этой работе.

Окружение: реальный UI локального dev-сервера, Chromium на компьютере, размеры/касание эмулируются. Auth HTTP-ответы синтетические; OAuth UI проверяется на управляемой заглушке границы SDK, без обращения к Apple/Google. Телефон пользователя и другие физические устройства не используются. Production не изменяется.

Инвариант: при переходе hint → loading → error/success/cancel в пределах выбранной формы координаты полей, primary-кнопки, Social-кнопок и карточки остаются неизменными. Сообщение ровно одно, 96px, под полями. Отмена находится внутри. Ошибки не скрываются таймером; ошибки ввода очищаются при редактировании, текст полей сохраняется. Переключение между паролем/восстановлением/кодом — отдельный явный переход, для него разрешено изменение состава формы.

| Элемент | Действие / ожидаемый результат | Матрица |
|---|---|---|
| Email/пароль | Некорректный email/пустой пароль/отказ → слот ошибки, aria-invalid/описание, сохранённый ввод | Обе роли, light/dark, 320/390/768/1440 и низкий экран |
| Войти / отмена | Загрузка → отказ/отмена → корректный статус, поздний ответ не заменяет новое состояние | Обе роли, запись геометрии с кадра до клика |
| Показать пароль | Значение и геометрия сохранены | Обе роли, повтор/быстрый повтор |
| Восстановление | Отправка → успешное письмо в том же слоте; поля/заголовок не заменяются; обратный путь | Обе роли, HTTP fixture |
| Apple/Google | Загрузка, отмена, SDK-ошибка, поздний ответ → только общий слот, правильный provider/role | Обе роли, SDK-boundary fixture |
| Код преподавателя | Email и поле кода постоянно занимают место; отправка/ошибка/отмена/новый код/cooldown/смена почты/назад | Синтетические HTTP-ответы, без реальной сессии |
| Выбрать роль | Отмена текущего действия, переход к роли; старый ответ не возвращает форму | Обе роли |
| Прокрутки | Начало/середина/конец страницы и длинного сообщения; фейды только нужных краёв | Телефон/ПК |
| Фокус/клавиатура | Enter/Tab/Escape, цели ≥44px, поля ≥16px, reduced motion | Локальный браузер |

Данные A/B: student@example.invalid / teacher@example.invalid; разные provider=apple/google, один синтетический отказ invalid_credentials, отдельный otp_expired. Recovery-success не означает отправку настоящего письма. Новый пароль/истёкшая ссылка требуют отдельной fixture-приёмки; реальная сессия, настоящая почта, OAuth callback и физические устройства вне полного E2E остаются NOT TESTED до явного результата.

До запуска все перечисленные клетки NOT TESTED. Состояния и координаты проверять по ожидаемым эффектам, не только по наличию элементов; сохранять падения. Итоговый PASS ограничивать фактически покрытой областью. Полная серверная/аппаратная матрица PARTIAL.


## Результат локальной приёмки

База SHA: `1d80bf3081f9ba4b518e5a91a6988c07568145ad`, рабочая копия с локальными изменениями. Состав изменяемых компонентов зафиксирован в `source.sha256`; это не production SHA. Production не выпускался.

- PASS: `browser-check.mjs` — 20 сочетаний: обе роли × light/dark × 320×568, 390×844, 768×1024, 1440×900, 1024×500. Геометрия карточки/полей/кнопок/слота сравнивается до и после статусов, кадры записываются до клика. Пароль, показ пароля, отмена и поздний ответ, восстановление, код, выбор роли; оба провайдера отдельно на 390/1440. `results.json`, `browser.log`, PNG и `*-frames.json`.
- PASS: `recovery-check.mjs` — 4 сочетания роли/390/1440: короткий новый пароль, истёкшая ссылка, сохранение нового пароля у преподавателя, одноразовое подтверждение у ученика. `recovery-results.json`.
- PASS: `edge-check.mjs` — 2 роли: invalid email/очистка, длинная ошибка с фейдами начало/середина/конец, отмена отправки кода и поздний ответ. Отрицательный контроль снятия фиксированной высоты обнаруживает смещение. `edge-results.json`.
- PASS: TypeScript, `check:ui`, `check:i18n`, `git diff --check`. Логи приложены; check:i18n выводит общий существующий словарь пропущенных строк, exit 0.
- Скриншоты для пользователя: 390×844 и 1440×900, light, обе роли. `*-error-review.png` / `*-loading-review.png` и `*-success-review.png` — полные окна; `*-card.png` — нативный screenshot области формы в том же браузере. Успех — подтверждение восстановления пароля, синтетический HTTP 200, настоящее письмо не отправлялось.

Попытка дополнительно удержать краткий успешный вход в fixture (`success-screenshots.mjs`) не завершилась: переход ученика завершает экран входа; этот прогон не засчитан. Для финальной демонстрации используется устойчивое успешное состояние восстановления. Ранние диагностические падения mock OTP/селектора провайдера сохранены, исправления fixture перепроверены полным успешным прогоном.

Ограничения: это приёмка локального UI с управляемыми HTTP/SDK ответами. Реальная почта, реальные Apple/Google callback, backend с пользовательской сессией, физический телефон, экранная клавиатура, Safari и полная матрица assistive technology/hover/focus/CPU throttling не проверены. Не делать из этих результатов вывод о полном серверном или аппаратном E2E. Для закрытия этих зон нужен отдельный разрешённый прогон на тестовых аккаунтах и устройствах. Телефон пользователя не использовался.

# Изоляция RPC ученика

Дата: 3 ноября 2026. Источник дефекта — legacy SECURITY DEFINER RPC, доверявшие UUID из запроса. Табличная матрица RLS этого не обнаруживала. Проверки проводились только на пяти синтетических учётных записях и их курсах; чужие реальные записи не запрашивались.

До исправления: анонимный клиент получал ID/группу по person_student_rows и учебный трек через student_track. Чужие ученик/преподаватель также получали курс другого fixture. set_course_order принимал чужое изменение. 8 отрицательных проверок FAIL, 4 разрешённых действия PASS. Это подтверждённый дефект контроля доступа; тест не устанавливает, использовал ли его кто-либо ранее.

Применена production-миграция 20261103063215_enforce_student_rpc_ownership. Чтение person_student_rows и student_track выполняется с RLS вызывающего пользователя, а вспомогательный поиск строк дополнительно ограничен Auth ID, владельцем преподавателя и доверенной ролью администратора. Запись порядка проверяет доступ к ученику внутри функции и не меняет существующий access_mode. Анонимный EXECUTE отозван. Служебный run_analytics_digest доступен только служебной роли/владельцу, не клиентам; его запуск для теста не выполнялся.

После исправления 12/12 PASS: чужое и анонимное чтение/изменение запрещено, свои данные доступны ученику/владельцу/администратору, перестановка сохраняет полный уровень доступа. Очистка fixture — без ошибок. [До](baseline.json), [после](fixed.json), [применённая миграция](migration-applied.json).

```sh
ISKRA_PRODUCTION_TEST=approved-isolated-fixture node scripts/security/checkProductionStudentRpcAccess.mjs
```

Это регрессия перечисленных RPC, а не полный аудит всех функций и всех исторических обращений. Остальные SECURITY DEFINER функции требуют оценки контекста; одно наличие grant в advisory не доказывает уязвимость. Общий трек и права повторно принимаются E2E после изменения.

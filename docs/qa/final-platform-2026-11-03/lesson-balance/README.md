# Остаток оплаченных занятий и права посещаемости

На реальном backend обнаружены ошибки дельт: изменение/перенос/удаление платежа и перенос/удаление посещаемости не корректировали остатки. Анонимный UI-повтор не был причиной: платежная запись действительно удалялась, а выданные занятия оставались. Также чужой преподаватель мог записать посещаемость чужому ученику, подставив ID своей группы.

Исходный production: 4 PASS / 8 FAIL в 12 сценариях, только на синтетических записях. Исправление — migration 20261103071256_sync_payment_and_attendance_credit. Два триггера считают дельту старого/нового события на INSERT/UPDATE/DELETE, блокируют строки учеников в одинаковом порядке, сохраняют ручной исходный остаток. Триггер работает с правами вызывающего пользователя. Дополнительные restrictive policies ограничивают посещаемость владельцем ученика/администратором; одного владения группой недостаточно. Отрицательное число купленных занятий запрещено на сервере.

После: 14/14 PASS — изменение/перенос/удаление, повтор статуса без двойного списания, параллельные платежи и удаления, запрет подмены ученика, запрет чтения чужой посещаемости через собственную группу, удаление синтетического ученика с каскадом. Ручная начальная выдача 10 занятий во всех сценариях сохранилась. Все fixture/Auth/платежи/посещения очищены.

Исторические балансы реальных учеников миграция не пересчитывает. По текущим оплатам нельзя безопасно восстановить ручные начальные выдачи и уже удалённые события; это отдельная сверка владельцем. Реальные деньги не переводились, платёжный провайдер не подключался.

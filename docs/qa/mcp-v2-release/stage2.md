# MCP v2, этап 2 — токен ИИ-помощника только через MCP (26.11.2026)

## Что было открыто (проверено на локальном стеке с настоящим OAuth-токеном)

OAuth-токен Supabase — обычный JWT учителя (`role authenticated`, `aal1`) с `client_id`. До этапа 2 им можно было:
- ходить в REST, Storage и Realtime напрямую под правами учителя, в обход прав, журнала и белого списка полей MCP (например, `students.phone` через подписку Realtime);
- вызывать Edge Functions, которые проверяют пользователя через `auth.getUser()`, а действуют сервисным ключом: сброс пароля ученика, выдача аккаунтов, Тестли, ссылки R2, ИИ-бюджет; админским токеном ещё и сброс пароля учителя, Telegram;
- в Auth v2.197 — сменить пароль учётной записи без MFA. **Прод работает на Auth v2.199: смену пароля, почты и удаление MFA токеном помощника он отклоняет сам** («OAuth client access tokens are not allowed»), проверено на той же версии локально.

## Что закрывает этап 2

1. `public.mfa_ok()` уже стоит ограничительной политикой `mfa_required` на каждой таблице `public` с RLS и на `storage.objects`. Для токена с `client_id` она теперь истинна только при заголовке `x-iskra-mcp-key` с секретом функции (в базе — sha256 в `private.mcp_gate_key`). Один пункт закрывает REST, Storage и Realtime (Realtime заголовков не передаёт).
2. `public.mfa_pre_request()` даёт помощнику понятную ошибку `assistant_direct_access`.
3. `mcp_client_state`/`mcp_gate`: подключение без строки прав больше не получает «прежние» права — `needs_consent`. Права создаёт только сессия Искры через REST, то есть через проверку MFA: согласие с украденным паролем без кода данных не откроет.
4. Функция `iskra-mcp` добавляет секрет ко всем своим запросам в REST/Storage (`gateHeader.ts`, только к этому проекту).
5. `_shared/mfa.ts`: `mfaPending()` отклоняет токен помощника — это сразу 13 функций; явная проверка добавлена в `mfa-backup`, `feedback-triage`, `social-oauth` (confirm-link).
6. Экран согласия показывает адрес, куда уйдёт доступ (`redirect_uri`), id и адрес клиента; незнакомый адрес — красное предупреждение. Имя подписано «имя приложение сообщает само».

## Порядок выпуска (prod)

1. Секрет `ISKRA_MCP_GATE_KEY` в функции (значение в чат не выводится), выкладка `iskra-mcp`. До миграции заголовок ни на что не влияет.
2. Выкладка 16 функций с новой `_shared/mfa.ts` — только после сверки, что на проде у них та же версия, что в `main`.
3. Дани в SQL Editor: миграция `20261126120000_mcp_request_gate.sql` + вставка хэша секрета.
4. Проверка: функции и политики на месте; обычные запросы без изменений; на проде 0 действующих подключений помощников.
5. Пуш в `main` (экран согласия, панель).

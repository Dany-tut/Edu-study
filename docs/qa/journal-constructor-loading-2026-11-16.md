# QA: стабильная шапка журнала и загрузка конструктора

- ID / область / границы проверки: JOURNAL-COUNT / CONSTRUCTOR-BOOTSTRAP; ПК, счётчик пункта «Журнал» и первое состояние Конструктора. Кешируется только число, scoped на owner ID; детали журнала всегда читаются штатным запросом. SQL/RPC и данные не менялись.
- Риск и причина приоритета: поздний ответ `journal_pending` менял ширину центральной навигации; lazy chunk Конструктора показывал общий экран ожидания, затем второй карточный skeleton.

- URL / версия / окружение / браузер и ОС / роль / реальные или подменённые данные: локально `http://127.0.0.1:5173/#/teacher/groups`; Microsoft Edge/macOS; авторизованный список не доступен в текущем локальном сеансе. Production до правки: `https://edu-study-app.vercel.app`, build `3284`.

- Данные: предыдущий счётчик хранится только как число, под ключом owner ID и максимум 6 часов; свежий ответ сервера заменяет кеш. Ноль/малый/двузначный счётчик проверен автоматическими проверками расчёта; авторизованный реальный счётчик визуально не проверен.

При открытии desktop-конструктора сразу видна карточная форма ожидания; общий экран не сменяется вторым skeleton. Состав/свежесть данных и защита редактора от записи поверх не загруженного содержимого не меняются.

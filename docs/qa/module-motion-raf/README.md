# Измеренный конечный скачок ширины вкладок

База: production fcddd30fb80cb743b66975319a5e98ce52bec763 (1.0.1910).
Проверка: CourseTrack целиком, реальные компоненты и stores, различимые fixture
ID модулей и уроков. Сервер и домашние виджеты не принимаются этим стендом.
Браузер: встроенный Chromium, десктоп 1280 px и узкое окно 390 px.

Метод отличается от прежних выборок DOM после клика: rAF-сэмплер встроен в
страницу, сохраняет буфер до pointerdown и все доступные кадры 850 мс после.
Кадры содержат координаты, размеры, transform, scrollLeft, выбранный модуль,
подписи уроков и временные отметки. Сэмплер работает до клика, без ожидания
«правильного результата». В отдельных прогонах есть 6–7 кадров до нажатия.

| Метрика | Опубликованный код | Исправленный код |
|---|---|---|
| Последний шаг ширины при переходе к 2, первый прогон | 1,015625 px | 0,015625 px |
| Последний шаг ширины при переходе к 1, первый прогон | 0,703125 px | 0,015625 px |
| Максимальный шаг координат после 280 мс, десктоп 2/1 | 1,015625 / 0,703125 px | 0 / 0 px |
| Прогретое повторение 2/1 | встречаются последние шаги 0,15625 / 0,140625 px | 0,0078125–0,015625 px |
| Узкое окно 390 px, последний шаг ширины | не измерялось до исправления | не более 0,015625 px |

Причина: финиш анимации `width: auto` возвращал естественную дробную ширину,
отличавшуюся от измеренной библиотекой конечной точки. Вкладка делала небольшой
последний скачок. Теперь ширина внутренней подписи заранее измеряется (включая
padding), обновляется при смене шрифта/размеров и анимируется числом. Сжатие всей
кнопки при нажатии заменено откликом прозрачности, не меняющим координаты.

Проверка самого теста: исходный код был возвращён в стенд и снова измерен
(before-warm.json), после чего восстановлено исправление (after-warm.json).
Первое нажатие повторных прогонов попадало в уже выбранную вкладку: это no-op,
его нельзя считать сменой модуля. Анализатор явно оставляет ему нулевой шаг.

`analyze.py` проверяет последний шаг <=0,05 px у исправления, отсутствие
перекрытия вкладок и принадлежность уроков активному модулю в каждом кадре.
Он также требует обнаружить скачок >0,1 px в baseline. Результаты summary.json;
полные кадры — before/after*.json. Не все кадры имеют идеальный интервал: на
исходном первом прогоне был интервал 191,6 мс; у исправления тоже были интервалы
до 49,1 мс. Это не основание обещать отсутствие всех фризов или приписывать
изменение FPS только исправлению: среда, прогрев и измеритель вносят нагрузку.

Доказанная область: устранён измеренный конечный скачок в этих fixture-прогонах.
Не доказано: полное отсутствие рывков на устройстве пользователя, Safari, CPU
throttling, вся главная с живым сервером, все темы и reduced-motion комбинации.
Для воспроизведения скопировать fixture.tsx в src/qaMotionRaf.tsx, fixture.html в
qa-motion.html, запустить локальный Vite и открыть страницу. Сэмплер начинает
запись до pointerdown; данные доступны в textarea#measure-output[data-run].

Итого сохранено 2108 rAF-кадров в пяти наборах. check:ui пройден в отдельной
рабочей копии с отдельным node_modules (check-ui.log). Сначала совместный cache
сборщика дал повреждённый временный bundle при параллельных проверках; повтор
в изолированных зависимостях прошёл. Исходники на время A/B фиксировались в
отдельном worktree, посторонние изменения главной рабочей копии не измерялись.

## Карточка: вход A → отмена → вход B → поздний A

Риск: поздний результат может подменить нового пользователя или кратко записать чужую сессию, хотя конечный снимок выглядит правильным. Ожидаемые ID заранее определены в скрипте из приватного исходного fixture: разные studentId/authId A и B. Секреты в отчёт не включены. Оба настоящих профильных ответа содержат ровно одну строку; принадлежность сверяется по ID, а не числу строк или имени.

| Действие | Ожидаемый результат | Факт и доказательство | Статус |
|---|---|---|---|
| Войти A, удержать настоящий ответ профиля | ID ответа = A; общей сессии A ещё нет | ownership-race.json, observed.A | PASS |
| Отменить A, ввести B и войти | Ответ принадлежит B, количество строк такое же; Auth и student_session = B | expected.B и observed.B/final | PASS |
| Отпустить ответ A после успеха B | Ни одна поздняя запись не принадлежит A; итог остаётся B | observed.writes и final | PASS |
| Намеренно записать A и немедленно восстановить B | Тест должен обнаружить краткую подмену при правильном итоговом B | ownership-negative-control/ownership-race-failure.json; exit 1 с `Late A storage write detected` | EXPECTED FAIL — чувствительность подтверждена |

Монитор Storage установлен через init script **до первого клика**, сохраняется через reload и записывает только вид операции, ID и время. Ожидаемые ID/assertions заданы в скрипте до действий. Подтверждены записи сессии и конечная принадлежность данных; видимость каждого пикселя и каждого промежуточного экрана этим монитором не доказывается. Контрольная инъекция воспроизводит симптом краткой устаревшей записи, а не полный откат исходников к прежнему дефекту.

Реальный драйвер: `scripts/security/checkLocalStudentLoginRace.mjs`. Обычный запуск — exit 0. Контроль — `ISKRA_QA_INJECT_STALE_AUTH=1` с отдельным `ISKRA_QA_OUTPUT`, ожидается exit 1. Нет новой регистрации, записи платежей или изменения учебных данных.

## Карточка: края прокрутки четырёх форм

Ожидаемый результат задан до действий: в начале при overflow прозрачен только нижний край; в середине — оба; в конце — только верхний; если всё помещается — ни один. Проверяются реальные scrollTop/clientHeight/scrollHeight и прозрачность первого/последнего цветового стопа вычисленной маски родителя фактического скроллера.

Заново пройдены четыре формы × две темы × четыре размера (1440×900, 1024×600, 320×568, 390×844): **32 конфигурации**, каждая с началом/серединой/концом. Это число конфигураций одного набора инвариантов, не 32 независимые функции платформы. Результат: edges/results.json, edges.log. Логика полей/парольного переключателя и клавиатурного восстановления сохранена в драйвере; регистрационные RPC визуального сценария остаются fixtures, реальные формы не отправлялись.

Отрицательный контроль насильно включает оба фейда в начале overflow. Тест падает на конкретной паре expectedTop=false/actualTop=true: edges-negative-control/failure.json, exit 1. Наличие mask != none больше не является достаточным условием успеха. Источник драйвера — auth-form-edges.mjs; контроль включается `ISKRA_QA_WRONG_FADE_EDGES=1` с отдельным каталогом результата. В конце контекст браузера закрывается, инъекция не сохраняется.

Эта проверка подтверждает набор верхнего/нижнего края вычисленной маски. Она не измеряет полный профиль прозрачности, восприятие контента за фейдом, все случаи вложенного/горизонтального overflow или интерактивность каждого элемента. Ранее просмотренные снимки в обеих темах дополняют утверждения, но не заменяют видеопроверку движения. Измерения в данном драйвере начинаются после стабилизации формы/скролла; отсутствие артефактов **до** этого ожидания не подтверждено.

## Общий остаток

- Новых продуктовых FAIL/блокировок в этой области нет; общая программа не завершена.
- Полный UI с сервером: владение сессией A/B, ошибка/повтор/отмена/обычный вход и учебный цикл подтверждены локально. Внешние провайдеры, SMTP, production и несколько настоящих устройств не приняты.
- Fixture UI: приглашения в визуальном прогоне; не засчитывать за регистрацию преподавателя или реальные данные курса.
- Движение: мониторинг Storage начинается до клика, но это не видео и не покадровое доказательство отсутствия старого UI. Полное визуальное движение, hit testing всех целей, CPU slowdown и reduced motion остаются NOT TESTED.
- Устройства: Chrome headless/viewport emulation; Edge/Safari/физический iPhone на этом runtime не проверены.
- Палитры и шрифты: две темы просмотрены в прежнем прогоне, но полный измеренный контраст, screen reader и zoom не сертифицированы.
- Полнота платформы: календарь, другие данные/переходы, модули, уведомления и все интерактивные элементы не становятся PASS из-за этих результатов. Прежние непроверенные клетки сохраняются.

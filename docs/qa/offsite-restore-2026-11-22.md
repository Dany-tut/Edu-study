# Проверка копии вне Mac и восстановления — 22.11.2026

## Сценарий и границы

Поручение Дани: сохранить независимую копию вне Mac, испытать восстановление
отдельно и посчитать полный бюджет PITR. Production используется только для чтения.
Продуктовые файлы/журнал/конструктор не меняются; их текущий фикс у другого владельца.

Копия размещается на существующем VPS в `/var/lib/iskra-private-backups`, вне webroot,
с каталогами 0700 и файлами 0600. SSH использует существующий ключ и известный host key.
Новые платные сервисы не подключаются. Доступ от www-data должен быть запрещён.
Старые копии не заменяются и не удаляются. При ошибке staging не становится готовой копией.

Восстановление: собственный Docker-контейнер `iskra-restore-*`, network=none,
без опубликованных портов, 0.5 CPU/512 MB. Никаких почтовых/Telegram/API вызовов.
Другие контейнеры и рабочая БД не останавливаются/не модифицируются.

## Действующее ежедневное задание

`dailyProductBackup.py` снимает потоковый SQL-дамп всех выбранных прикладных,
Auth/Storage таблиц в одной транзакции pg_dump, отдельно — схему и metadata
ролей/расширений/защитных event triggers. Список схем определяется из каталога.
Provider-internal схемы, Vault decryption keys, настройки Auth/SMTP и внешние
видео не входят. Файлы Storage скачиваются по metadata именно из SQL-дампа.
Схема снимается отдельно от данных; Storage может измениться после снимка —
ошибка скачивания/размера отменяет публикацию новой копии.

Manifest format 4 содержит контрольные суммы артефактов и число строк COPY.
Окончательная папка на VPS появляется только после проверки хешей. Ежедневная
задача требует работающих Mac, Docker, сети и CLI/SSH авторизации; модель не запускается.
Политики автоматического удаления копий нет.

Это приёмка восстановления БД/файлов, а не полного запуска приложения/Auth/SMTP.
Физические ПК/iPhone/iPad/Android и пользовательский UI в этой задаче не проверяются.
PITR не включён; отдельный аудит всей безопасности приложения не проводился.

## Бюджет PITR

Организация Edu platform — Free, доступен один проект. Для одного проекта:
Pro $25 + Micro compute около $10 + PITR 7 дней около $100 − compute credits $10
= около $125/месяц до налогов и превышения включённых лимитов.
Актуальная страница Backups разрешает PITR на всех compute sizes; Small не обязателен.
Со Small (около $15) итог около $130/месяц. Тарификация compute
и PITR почасовая, сумма зависит от длины периода. PITR 14 дней — около $225,
28 дней — около $425 с Micro (со Small соответственно $230/$430). Платные услуги не включались.

В ходе подготовки обнаружены особенности bootstrap образа Supabase: временный
postmaster принимает соединения до завершения инициализации; финальный процесс
в закреплённом Nix-образе называется `.postgres-wrapp`; pg_catalog нельзя создавать
как пользовательскую схему. Рецепт учитывает эти условия. Повтор bootstrap разрешён
только для изолированного контейнера, где все прикладные таблицы пусты.

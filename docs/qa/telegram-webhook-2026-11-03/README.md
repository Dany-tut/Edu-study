# Telegram webhook: отказ без конфигурации

Сценарий: неподписанный внешний запрос не должен писать входящие сообщения от имени произвольного Telegram chat_id. Слой проверки — реальный обработчик с изолированным DB stub, затем production endpoint с пустым запросом без отправки сообщений людям.

До исправления: TELEGRAM_WEBHOOK_SECRET отсутствует; код `secret && mismatch` пропускал запрос. Запрос {} к production вернул200; подстановка синтетического message в изолированном обработчике достигает записи. Боевые поддельные сообщения не создавались.

Исправление: отсутствие секрета или неверный заголовок возвращают403 до разбора/записи. Регрессия scripts/checkTelegramWebhook.mjs выполняет настоящий handler:4 запрета (нет/неверная конфигурация/заголовок), пустое корректно подписанное событие, корректно подписанное синтетическое сообщение. Всего6PASS; исходная версия даёт ожидаемый FAIL. Регрессия включена в check:diagnostics.

Отсутствуют параметры Telegram: полноценные входящий update/ответ из админки/уведомление заявки не приняты. Настройка потребует одного секретного значения на сервере и у Telegram setWebhook; это не исправляется созданием случайного секрета только на одной стороне.

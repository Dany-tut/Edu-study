# Прямая ссылка на карточку ученика

База рабочей сборки `1d80bf3081f9ba4b518e5a91a6988c07568145ad`. Локальный Vite, Chrome, светлая тема, 1440 × 850 и 390 × 850. В маршрутах работали настоящие компоненты кабинета. Источником журнала служил fixture с двумя разными учениками. Проверяющий — Codex.

| Действие | Ожидаемый и полученный результат |
|---|---|
| Открыть ссылку A при сохранённом в teacher-nav ученике B, затем обновить страницу | Имя A в видимой карточке и в версии для печати |
| Заменить адрес A ссылкой B и открыть копию в новой вкладке | Имя B в обеих вкладках |
| Подставить отсутствующий ID | «Ученик не найден», карточки A и B отсутствуют |
| Нажать «Назад» | Восстановлен адрес журнала |
| В обзоре журнала выбрать A, открыть «Профиль из групп» и закрыть | Шторка открыта с ID A в адресе, после закрытия восстановлен адрес журнала |
| Прокрутить отдельную карточку | [Начало, середина и конец на двух размерах](scroll.jpg) |

Отдельный тест локального Supabase запустил десять регистраций одновременно через Auth API. Для каждой использовались свой email и своё приглашение. Все десять получили разные UID, применили приглашение и записали по ученику. Запрос всех десяти ID от каждой учётной записи вернул только собственную запись. Тестовые записи удалены после проверки.

Не проверялись production, оформление десяти регистраций через браузер, физические устройства, тёмная тема, покадровые переходы и доставка почты. Браузерные проверки маршрута и проверки изоляции на сервере проводились отдельно.

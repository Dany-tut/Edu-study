# Искра — браузеры на физическом iPhone, 3 ноября 2026

Safari и Яндекс отрисовали форму преподавателя на iPhone 17 Pro. В обоих браузерах проверены ввод Email/пароля и сохранение значений после вертикального swipe. Кнопка входа не нажималась; использованы только ui-only@example.invalid и фиктивный пароль.

## Safari

Статические файлы dist обслуживал отдельный временный XCUITest runner через NWListener, привязанный только к loopback телефона. CSP connect-src none блокировал API и телеметрию. Пройдены форма, фокус полей и прокрутка. Снимки: safari-login.png, safari-password.png, safari-scroll.png. Этот проход предшествовал последнему изменению геометрии формы.

## Яндекс

Loopback сначала вернул ERR_CONNECTION_FAILED. Проверка продолжена через временный HTTP-сервер на частном Wi-Fi адресе Mac, без публикации в интернет. Сервер отдавал только index.html и публичные runtime assets dist, без listing, API, исходников и sourcemaps. Ресурсы размещались под случайным 128-битным префиксом. Корневой index разрешался только для подтверждённого peer IP тестового телефона; другим клиентам GET / возвращал 404. CSP сохранял connect-src none, form-action none, frame-src none и object-src none.

Исходный dist не менялся: сервер переписывал только пути Vite preload и публичного trainer.png для размещения ресурсов под префиксом. Первоначально trainer.png не входил в whitelist; после исправления стенда выполнен отдельный успешный визуальный проход с загруженной картинкой. Итоговый чистый снимок: yandex-lan-form.png.

Из-за нормализации pathname маршрутизатором форма должна загружаться на /, а ресурсы — под префиксом. XCTest.open периодически зависал при загрузке accessibility Яндекс; восстановление terminate/launch позволило проверить уже открытую правильную форму. Последний визуальный проход успешно открыл адрес штатно через новую вкладку и адресную строку: URL вводился посимвольно, полное значение проверялось до кнопки Go. Разрешения локальной сети/firewall не запрашивались; настройки системы и браузера не менялись.

Отправка форм, реальная авторизация через эти браузеры, production API и полная матрица размеров в этот браузерный проход не входили. Публикация и коммиты не выполнялись.


## Chrome 157 — финальная проверка

Реальный iPhone 17 Pro: devicectl подтвердил iOS 27.2 (24B119), Chrome 157.8103.24. Версия Xcode/SDK — 27.1; её не следует путать с версией самого устройства.

Заморожена отдельная копия dist 1.0.1893 с конкретным TeacherLoginPage-D_UnzUKA.js. Номер версии в общем рабочем дереве повторялся, поэтому точный проверенный chunk и его SHA256 записаны в chrome-result.json. Запрос этого chunk от телефона подтверждён журналом временного сервера. API, telemetry, form-action и внешние frame/object заблокированы CSP. Форма не отправлялась, разрешения и системные настройки не менялись.

Первый проход выявил реальное перекрытие: поле пароля y491…546 и глаз попадали под Chrome autofill/accessory panel, начинающуюся на y475. После исправления компактного вида при фокусе два свежих открытия подтвердили ввод и переключение глаза с сохранением клавиатуры/значений. Их suite chrome-repro.xcresult завершился FAIL только из-за неверной тестовой предпосылки: повторный свайп уже у нижнего предела не обязан двигать форму.

Финальный полный chrome-payload.xcresult — PASS: test01ExistingFixedPage 25.321 с и test99Cleanup 0.939 с. После снятия фокуса тест вернулся к началу и выполнил явную прокрутку до конца: Email y441 → y184. Текст обоих полей сохранился. Пароль y379…434 находится выше панели; AX-переключатель глаза 45×45 pt. Показ/скрытие подтверждены изменением label и реальным видимым текстом/маской; клавиатура сохраняется. Вход по коду и отправка писем для финального scroll не потребовались.

Снимки: chrome-form.png, chrome-keyboard.png, chrome-eye-shown.png, chrome-scroll-middle.png, chrome-scroll-start.png, chrome-scroll-end.png. На них только локальная Искра и собственные фиктивные данные.

Стенд: собственная вкладка открыта через devicectl --payload-url с документированной [схемой Chrome для iOS](https://github.com/chromium/chromium/blob/main/docs/ios/opening_links.md). Это устранило нестабильное ожидание accessibility внутри XCTest.open. Только в временном UITest runner отключено ожидание quiescence процесса Chrome по механизму [Appium WebDriverAgent](https://github.com/appium/WebDriverAgent/blob/master/WebDriverAgentLib/Categories/XCUIApplicationProcess%2BFBQuiescence.m); готовность контролировалась явными waiters, геометрией и снимками. Код приложения и настройки Chrome этим механизмом не меняются. Реальные учётные данные и production API для теста не использовались.

Все собственные вкладки закрыты; временный сервер остановлен, повторный TCP connect вернул ConnectionRefusedError. Путь к полному Chrome harness: /tmp/iskra-chrome-uitest-path. Снимки и chrome-result.json не содержат чужих страниц, контактов или системных уведомлений. Отправка входа и остальные размеры/темы не проверялись этим проходом.

# Искра: гонка отложенного клика кадра и Play/Pause

Карточка до проверки: `/tmp/iskra-player-repro-card.md`. Ответственный за исправление и проверку — текущий чат плеера. Область — native video в fixture UI, без серверных данных и смены ученика/урока; A/B ownership здесь неприменимо.

База: `c688b13db9f049bad523334495c9f35ff7e7fd8f` + локальный patch.
SHA-256 итогового `LessonVideoPlayer.tsx`: `153a88995f72f27ef9263011d982951278c22d499ed45fffdc7e38c0ed235af4`.
Изолированная копия: `/tmp/iskra-player-race-isolated`, Vite `http://127.0.0.1:5198`, Edge/macOS, headless, локальный MP4. Исходник плеера во время итогового изолированного прогона не менялся.

## Подтверждённая причина

На паузе: клик по кадру → через 80 мс явный Play → видео начинает играть → старый таймер одиночного клика (220 мс) видит новое состояние и снова вызывает Pause. Это воспроизвелось на исходном коде с первой попытки. Отдельно: два быстрых клика по разным зонам перезаписывали ref таймера, оставляя предыдущий таймер без возможности отмены.

Исправление отменяет отложенный клик при явном управлении, перемотке и смене fullscreen. Второй клик в другой зоне отменяет предыдущий таймер до записи нового. Обычные одиночные и двойные жесты сохраняются.

| Элемент / сценарий | Независимое ожидание | Проверка / доказательство |
|---|---|---|
| Кадр → Play панели до дедлайна | После дедлайна video.paused=false, currentTime растёт | Регрессия `scripts/checkLessonPlayerTapRace.mjs`, события до клика, media time после дедлайна |
| Кадр → центральный Play | То же | Fullscreen и обычный десктоп; обычный мобильный центр отдельно не принят |
| Кадр → явный Pause | После дедлайна video.paused=true | Та же регрессия |
| Две зоны кадра → Play | Ни один старый таймер не останавливает видео | Отдельный сценарий orphan timer |
| Normal → fullscreen → Pause → Play → выход → повтор | Управление доступно; явные команды сохраняют действие | Повторные циклы, hit testing каждой используемой кнопки |
| Одиночный / двойной клик кадра | Пуск / переключение fullscreen | Та же регрессия |
| Volume, rate, seek, отклонённый play() | Действия работают, после отказа доступен повтор | `checkLessonPlayerBrowser.mjs`, Edge, четыре размера прошли до последней правки orphan timer |

## Доказательства и границы

- Исходный сбой: `/tmp/iskra-player-race-before.json`, `/tmp/iskra-player-race-before.png`.
- 24 цикла с реальными задержками и исходным дедлайном 220 мс: `/tmp/iskra-player-real-stress.log`, `/tmp/iskra-player-stress-trace.json`; прошли после первой части исправления, до добавления защиты orphan timer.
- Итоговая изолированная регрессия: `/tmp/iskra-player-isolated-timing.log`, `/tmp/iskra-player-isolated-timing/`. Для воспроизводимого перекрытия действий тест увеличивает только TAP_MS в отдаваемом модуле с 220 до 1000 мс. Видео, rAF, мышь и проверка роста currentTime работают в реальном времени.
- PASS итогового изолированного прогона: 1440×900, 844×390, 390×844, 320×568; обычный/полный экран, повторные переходы, явные Play/Pause, одиночные/двойные клики, две зоны, hit testing и реальный рост currentTime. Мобильная геометрия проверена в десктопном Edge, не на устройстве.
- Отрицательный контроль orphan timer на итоговом тесте также дал ожидаемый FAIL именно на `Two frame zones must not leave an orphan timer after Play`: `/tmp/iskra-player-isolated-negative-orphan.log`, `/tmp/iskra-player-isolated-negative-orphan/1440-trace.json`.
- Отрицательная проверка с отключённой отменой таймера дала ожидаемый FAIL: `/tmp/iskra-player-negative-clock/1440-trace.json`. Это проверяет способность теста обнаружить дефект, а не только положительный цикл.
- Первые дополнительные прогоны в общей копии прерывались до готовности стенда; их не считать PASS. Старые ошибки очистки trace, скрывавшие причину прерывания, исправлены в тесте.
- `npm run check:ui`, `npx tsc --noEmit` и `git diff --check` прошли.

# MCP интеграция Искры: карточка до запуска

База ff9f5c4 (актуальный origin/main при выделении worktree); final SHA и hashes фиксируются в отчёте. Ответственный backend/приёмка — чат полного QA; UI — «Профили Искры, друзья и совместные квизы», отдельная ветка.

Риск: доступ Claude к чужим курсам, неподтверждённый OAuth, запись в опубликованный курс, дубли/потерянные данные при повторе, ложный статус подключения. Среда: production Supabase, отдельные синтетические преподаватели A/B и ученик; реальные auth/OAuth, fixture клиент отдельно от настоящего Claude. Секреты только в приватном cache, очистка точных собственных UUID.

Ожидания: endpoint отвечает на discovery до входа и отклоняет tools без токена; OAuth PKCE/S256 с согласиями, запретом доступа/повтором и отзывом; пользовательA видит/создаёт/изменяет только свои черновики. Чужие/опубликованные курсы неизменны. Ученик не пишет. Созданные курс/модуль/урок/тест видны в кабинете A, B не видит. Отозванный grant не допускает дальнейшие операции. Каждый результат сверяется с IDs и сервером. Ошибки retry/позднего ответа не подменяют текущий аккаунт/состояние.

UI: Настройки → Интеграции → Claude(MCP); loading/нет подключения/error/подключён/отозван, обновление статуса и копирование адреса, отмена/подтверждение отзыва. Матрица 320/390/1440, light/dark, клавиатура/Escape, overflow начало/середина/конец. Владелец UI предоставляет отдельный протокол. Реальный внешний Claude требует отдельного теста; успешный синтетический MCP-клиент не засчитывается как Claude.

## Проверки

Выполнять последовательно, из корня репозитория:

- `node scripts/checkPasswordResetSecurity.mjs` — PASS, 28 сценариев, реальный код обработчиков с mocked Auth/DB. Проверяет отказ до смены пароля и записи в БД. Не доказывает подлинную проверку JWT или RLS.
- `ISKRA_PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node scripts/checkSanitizeSecurity.mjs` — PASS, 5 XSS-проб в Chrome и сохранение простого форматирования. В этом прогоне модуль: `/tmp/iskra-icon-qa/node_modules/playwright/index.mjs`. Нужен установленный Google Chrome на macOS; скрипт не скачивает браузер и блокирует сетевые запросы.
- `npm run check:prose` — PASS.
- `npx --no-install tsc --noEmit` — PASS (frontend; Edge Functions не охватывает).
- `npm run check:ui` — PASS. Интерфейс и его scroll-layout не изменялись; визуальная проверка экранов не выполнялась.
- `npm audit --json` — exit 1 из-за advisories, полный результат в npm-audit.json.

Ресурсы перед запуском: memory_pressure free 29%, свободный диск около 19 GiB. Нагрузка, установка Docker/VM и параллельные тяжёлые процессы не запускались.

## Следующая работа и допуск

NO-GO для беты с реальными данными остаётся. Сначала устранить назначение привилегий через регистрацию/профиль, перейти с хранения паролей на безопасный процесс приглашения/восстановления, расширить очистку HTML, проверить чистую тестовую БД и межаккаунтную матрицу. Затем env/bootstrap, зависимости, E2E, приватность аналитики, восстановление и Windows-проверка. Рекомендации по маркетингу, числу участников и косметическим изменениям требуют продуктового решения и не закрывают безопасность.

Для выпуска отдельно проверить серверный app_metadata.role у законных администраторов. Изменения Edge Functions требуют отдельного выпуска; один frontend deployment их не доставит. Следовать docs/releases.md, не публиковать текущую общую грязную копию.

## Результат

Повторяемый автоматический прогон `scripts/security/checkLocalUserCycle.mjs` — **7 PASS / 0 FAIL**:

1. Ученик открывает приглашение и регистрируется через интерфейс. Настоящий Auth связывается с карточкой; temp_password остаётся NULL.
2. Открывает назначенную домашку, пишет краткий/развёрнутый ответ. Черновик переживает reload в том же браузере.
3. Сдаёт через интерфейс. Сервер сохраняет попытку со статусом submitted, итог NULL, reviewRequired=true.
4. Преподаватель входит через отдельный браузерный контекст, открывает очередь и видит настоящие ответы.
5. Публикует 90% и комментарий кнопкой «Сохранить и продолжить». На сервере тот же attempt_id.
6. Ученик входит в новый пустой браузерный контекст, видит 90%, комментарий и исходные ответы в истории попытки.
7. После ещё одного reload результат тот же; на сервере ровно одна попытка.

Преподаватель/курс/модуль/приглашение/назначение подготавливаются настоящими локальными API как fixtures; клики создания курса и назначения в редакторе в эти семь шагов не входят. Учитель для replay проходит реальный API-процесс signup → admin invite → apply_teacher_invite. Supabase API не подменяется. Браузер один, контексты ученик/учитель/ученик последовательные. Запросы за пределы localhost заблокированы.

## Что найдено и исправлено

Полный путь поймал крах teacher workspace `RangeError: Invalid time value`. У связанной с уроком домашки могло отсутствовать assignedAt, а scheduled_date сохранялась как DD.MM.YYYY. Ненормализованная строка попадала в weekOf().

В `studentWorks.ts` дата нормализуется через journalDate; weekOf отвергает недопустимые дни и месяцы, не вызывая toISOString на Invalid Date. Существующие изменения этого файла сохранены. Добавлены тесты legacy даты, несуществующего месяца/дня и корректного подсчёта недели. `npm run check:course-journal` — PASS; затем полный browser replay — PASS.

В текущем синтетическом `tempFactsQA.tsx` также добавлен обязательный isHard:false для двух тестовых заданий, блокировавших общий tsc. Остальное содержимое стенда сохранено. Финальный `npx --no-install tsc --noEmit` — PASS.

## Воспроизведение

При запущенном локальном стенде с приватным `/tmp/iskra-local-security/status.json`:

```
node scripts/security/checkLocalSupabase.mjs
node scripts/security/checkLocalPayments.mjs
ISKRA_PLAYWRIGHT_MODULE=/tmp/iskra-icon-qa/node_modules/playwright/index.mjs node scripts/security/checkLocalUserCycle.mjs
node scripts/security/checkLocalEdgeAuth.mjs
python3 scripts/security/checkLocalRestore.py
node scripts/security/checkLocalStorageRestore.mjs
npm run check:course-journal
npm run check:ui
npx --no-install tsc --noEmit
```

Последовательно; один браузер, без параллельных тяжёлых операций. Fixtures/status/backup содержат только сгенерированные LOCAL credentials и synthetic data, остаются с приватными правами в /tmp. В репозиторий скопированы только отчёты и снимки без паролей/токенов. Source hashes — в summary.json.

## Граница готовности

Основной путь больше не является непроверенной гипотезой: он воспроизведён, найденный крах исправлен. Это позволяет переходить к приёмке кандидата на отдельном стенде.

**Доступ реальных пользователей в production пока не согласован и не подготовлен к выпуску.** Остаются: очистка исторических паролей и проверка происхождения существующих ролей в целевой среде; окончательный XSS/dependency triage; расширение проверок мутаций/сетевых сбоев, Windows Chrome/Edge; актуальная схема целевого сервиса вместо одного локального snapshot; чистая отдельная release-копия с только относящимися к задаче изменениями.

Особенности нынешнего клиента: черновик до сдачи сохраняется в localStorage текущего браузера; на другом устройстве он пока не синхронизируется. В свежем сеансе исходные сданные ответы доступны в истории попытки, но пустые disabled поля основной формы не заполняются ими автоматически. Эти ограничения не скрыты за общим PASS.

Локальные контейнеры и frontend после работы остановлены; synthetic volumes и приватные backup сохранены. Чужие контейнеры/файлы не очищались. Ресурсная защита не отключалась; по ходу тяжёлых общих проверок снова сработал дисковый порог, после завершения функциональных тестов. Это не опровергает их результаты и не является нагрузочной оценкой продукта.

# Искра · Допуск чистого кандидата iPhone

Этап 1 — чистая рабочая ветка. Этап 2 — приёмка точной сборки. Этап 3 — fast-forward в актуальный main, деплой Git-интеграцией и сверка полного SHA в двух файлах на production. Предыдущий план улучшений UI и этот релизный допуск учитываются отдельно.

## Что подтверждено до окончательной приёмки

- R5 выявил унаследованный кадр со старой альфой после начала прокрутки. Выпуск удержан по указанию пользователя. На R6 и R7 область верхнего растворения уже существует до движения и помещается в исходном пустом отступе. На 320/390 в светлой и тёмной темах больше нет кадров со старой маской. Кнопки, заголовок и первая строка остаются читаемыми.
- На R6 реальная авторизация ученика завершалась возвратом на выбор роли. R7 исправляет выбор экрана при корневом адресе и сохранённой карточке ученика. На физическом iPhone подтверждены вход, восстановление кабинета после перезапуска и открытие своего ДЗ. Явный маршрут выбора роли сохранён.
- Для R7, SHA 1bca7601d798abe9edd965a3eb20639804e4cfb4, прошли release:check и CI. Отдельная проверка Chrome iOS прошла на физическом устройстве. Ввод, показ пароля, прокрутка, три положения маски, закрытие вкладки подтверждены в ../chrome-rc-2026-11-03/R7-loopback.md. Это чтение формы без отправки. Полный цикл ДЗ на Mac, проверенный ранее, отдельно от нативного прогона.
- При моделировании 503 на повторном GET standalone homework R7 сбрасывает ранее загруженную работу. Сервер при этом хранит назначение. Для допуска нужен повтор с исправлением, контроль пустого успешного ответа и изоляции учеников.
- Аппаратный прогон ДЗ использует изолированные роли и фактический API через взаимно аутентифицированный тестовый канал. Сессия создаётся через штатную форму входа. Полные xcresult с реквизитами тестовых аккаунтов не публикуются.

## Статус

Публикации из этой задачи не было. Проверка полного цикла ДЗ на iPhone и допуск финального SHA остаются открыты. Параллельные изменения main требуют обновления базы и нового прогона точного SHA перед выпуском. Общая пауза снята после выпуска db86facd.

Физический iPhone 17 Pro, iOS 27.1. SHA 1bca7601d798abe9edd965a3eb20639804e4cfb4, версия 1.0.1952. Отдельная QA-подпись и синтетический backend. Подтверждены ввод через штатную форму, загрузка собственного кабинета, сохранение сессии после холодного запуска, открытие работы A, сохранение черновика после перезапуска, отправка первой попытки, возврат преподавателем с комментарием, новый вход ученика и вторая сдача под новым ID попытки в той же записи прогресса. Это промежуточный прогон: нормальный выход ученика выявил гонку, после которой для продолжения пришлось выйти штатной кнопкой кабинета преподавателя. Обход не считается PASS выхода ученика. Первая и повторная попытки сопоставлены с локальными серверными IDs. Для базы A/B отдельная read-only проверка; результаты macOS или браузерной эмуляции в этот список не включены.

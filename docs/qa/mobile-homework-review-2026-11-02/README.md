# Искра — мобильная проверка обычных ДЗ

2 ноября 2026. Изменения локальные, production не публиковался.

## Реализовано

Обычные ДЗ в MobileTeacherReview теперь открываются на телефоне. MobileHomeworkReview показывает сохранённые условия и ответы через общий BasicAnswersList, итоговый процент либо баллы каждого задания, комментарий и закреплённые действия. Один внешний скроллер MobileScreen отвечает за всю ленту и её фейды. Нижняя навигация скрыта внутри работы, круглая кнопка возвращает в очередь; нативный заголовок использует существующий UIKit-мост.

Публикация вызывает общую reviewHomework с id сдачи и expectedAttemptId, сохраняя прежние фото и доску проверки. Реализация не создаёт другой путь записи оценок и не меняет схему базы. После успеха отдельное подтверждение предлагает следующую непроверенную работу. После последней — возврат в очередь. Реальная очередь перезагружается после успешной записи.

Черновик хранится через общий sessionStorage-механизм по ДЗ, сдаче и попытке; переживает уход в очередь и перезагрузку той же вкладки. При смене попытки используется новый ключ. Очистка — только после успешной публикации. При переполнении хранилища показывается предупреждение. Во время запроса повторная отправка, изменение формы и выход назад блокируются. Просмотр чужого кабинета не разрешает публикацию.

useHomeworkSubmissions теперь возвращает loading/error и отбрасывает запоздалые ответы после смены ДЗ/размонтирования. Ошибка загрузки не выдаётся за пустую очередь; доступна кнопка повтора.

| Возврат с комментарием без оценок | Разрешён |

## Изолированный стенд

При запущенном Vite открыть /dev-mobile-review.html. Включение «Ошибка сохранения» заставляет адаптер вернуть false после задержки; счётчик показывает число вызовов. «Баллы по заданиям» включает два задания с максимумами 2 и 3. Все сохранения на стенде остаются в памяти, база не используется. Стенд рендерится только в DEV и не включён во входы production-сборки.

Обычная DEV-очередь также использует синтетические сдачи с явной подписью «Учебный пример». Демонстрационные вердикты живут в текущем экземпляре очереди; это не сохранение в базе.

## Границы

Записи реальных оценок в живую базу не выполнялись. Сквозная проверка UI → реальный API → база под авторизованным преподавателем остаётся необходимой перед выпуском. Ошибка/повтор проверены через изолированный адаптер, а не отключение сети у production. Системная клавиатура, VoiceOver и жесты на физическом iPhone не проверены. Новый экран поддерживает комментарий текстом; добавление новых фото/доски и работа с ИИ здесь не реализованы. Существующие вложения проверки при публикации сохраняются.

## Уточнение: soft edge нижних действий

MobileScreen измеряет фактическую высоту нижней панели (ResizeObserver). Контент растворяется альфа-маской за 56 px до её верхнего края; под кнопками он полностью прозрачен. Цветной градиент-подложка не используется. Резерв под последние поля также рассчитан по высоте панели. Удалены неиспользуемый helper с цветной подложкой и ручной запас 70 px в редакторе. Правило закреплено в docs/ui-rules.md.

Визуально проверены начало, середина и конец на 390 × 844, а также рост панели при появлении ошибки: её верх меняется с 696 до 638 px, и маска следует за ним. Скриншот soft-edge.png показывает нижний фрагмент.

## Общие компоненты

ScrollFade и HScrollFade теперь по умолчанию используют alpha mask вместо цветного overlay. Удалены разделительные линии и собственные подложки нижних действий в обоих рабочих пространствах проверки (hr/jh). Нижний фейд тела MobileSheet перед footer увеличен до 48 px. Modal и OverlayScrollArea уже используют маски и не рисуют отдельную полосу перед footer.

Общие вертикальный и горизонтальный скроллеры визуально проверены на временном стенде: начало, середина и конец при 390 × 844, десктоп при 1280 × 900. В середине вычисленные CSS-маски прозрачны с обеих сторон, в конце остаётся только входной фейд. Временный стенд удалён. TypeScript и check:ui прошли.

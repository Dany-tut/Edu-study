# Приёмка сохранения расписания и диагностики · 22 ноября 2026

- Область: атомарная синхронизация расписания курса, сохранение ID/журнала, диагностика db_error.
- База: ec8832fd; итоговый SHA фиксируется Git-коммитом и квитанцией выпуска.
- Проверяющий/исполнитель: текущий чат Codex.
- Данные: синтетические A/B, отдельный PostgreSQL PGlite; production только read-only.
- Риск: перенос цепочки дат нарушает немедленный UNIQUE; частичное сохранение и невидимый отчёт.
- Инварианты: либо весь план календаря, либо ничего; ID/статусы/заметки/посещаемость остаются;
  чужой курс не изменяется; ошибка доставки остаётся в outbox; черновик удаляется только после успеха.
- Сценарии до прогона: перенос цепочки; обмен дат; реальное совпадение; повтор после успеха;
  конфликт с чужим курсом; попытка доступа B к A; ошибка после удаления/обновления; пустой план;
  удаляемый слот с журналом; db_error offline → restart → delivery; сводка включает db_error.
- UI: оформление/overflow не меняются. Логика общая для ПК/iPhone/iPad/Android.
- Не приняты заранее: физические устройства, полный авторизованный production UI и пользовательский черновик.

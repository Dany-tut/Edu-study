# Горизонтальная перестановка виджетов

План приёмки до browser-теста. База ca24c00f + patch deskWidgetSizing.ts/DeskCanvas.tsx; итоговый чистый SHA — в истории выпуска.

История: преподаватель в режиме редактирования тянет карточку на соседа в том же ряду. Превью и сохранённая раскладка используют одно правило. Переставляется только затронутый горизонтальный интервал, остальные ряды сохраняют x/y/w/h. При вертикальном переносе и resize сохраняется раздвигание вниз; свободный перенос не уплотняет намеренные пустые клетки.

Обязательные варианты: одинаковые и разные ширины, влево/вправо, верхние метрики и нижний ряд 3×5/3×5/2×5, несколько соседей, свободные клетки, разная высота (без недопустимого наложения), быстрый отпуск и cancel, повтор/обратный путь, reload сохранённой раскладки. Инварианты: целые координаты, уникальные ID, размеры не меняются, нет пересечений, неподвижные ряды не затронуты. Данные A/B — разные ID типов карточек, сравнивать именно ID, а не количество строк.

План fixture UI: настоящий DeskCanvas, фиксированные различимые карточки; viewport desktop и phone, обе темы. Измерять live-раскладку и commit, действие реальной мышью. Это не полный E2E сохранения в БД и не физический телефон. Изменения запросов/данных отсутствуют; loading/error/поздний ответ не считать проверенными. Новых областей прокрутки нет. Покадровую плавность и физические устройства отмечать отдельно от финальной геометрии.

## Результат приёмки изменения

- Чистые функции: 147 перестановок для ширин [1,1], [2,2], [3,3,2], [2,1,1,2], [1,2,3,1] и высот 1/2/5; целостность ID, размеры, отсутствие пересечений, неизменный нижний ряд, сериализация/reload. Отдельно точный порядок верхнего и нижнего ряда, обратный путь, свободное размещение с пробелами, вертикальный fallback. Исходные массивы не мутируются.
- Fixture UI: настоящий DeskCanvas, настоящие компоненты, перехваченные ответы REST/Functions. В контенте — empty/demo fallback; это не серверный E2E. Десктоп 1440×900, светлая тема: первый перенос вправо-налево и ещё 5 циклов туда-обратно; нижний ряд во всех rAF-выборках сместился на 0 px. Наблюдение запускалось ДО pointer drag.
- Нижние карточки 3×5/3×5/2×5: задачи из x=6 перешли в x=3, напоминания из x=3 в x=5, календарь и все верхние карточки неподвижны. Перенос 2×1 между двумя 1×1 также сохранил весь нижний ряд.
- На viewport 390×844 в тёмной теме две метрики поменялись местами; календарь под ними сместился на 0 px. Ввод мышью при узком viewport, не физический touch-тест.
- Reload fixture sessionStorage сохранил точные ID, transform и размеры переставленного смешанного ряда. Серверное persistConfig не проверялось.
- Доказательства: browser-motion.json (rAF-агрегаты, координаты, число кадров); horizontal-reorder-desktop.png и horizontal-mobile-dark.png в каталоге визуализаций чата. Видимое движение активной карточки по Y до ~1.5 px у метрик и ~4.3 px у высокой карточки связано с существующим drag scale; остальные ряды/соседи по Y неподвижны. Это проверка смещения рядов, а не гарантия идеальной частоты кадров.
- Негативный контроль: временное выключение горизонтальной ветки восстановило старое смещение вниз; тест упал (в y=0 осталось 3 метрики вместо 4). Код восстановлен, регрессия повторяется в release:check.
- TypeScript: npx tsc --noEmit прошёл.

Осталось непроверенным: реальный pointercancel, отдельный быстрый pointerup без pointermove, физический телефон/планшет, клавиатурное управление drag (не добавлялось), CPU slowdown, полный серверный E2E и все сочетания контента/тем. Правка не переносит overflow; существующие фейды и resize-алгоритм сохранены. Статус: PASS для перечисленных горизонтальных сценариев, PARTIAL для общей поэлементной матрицы.

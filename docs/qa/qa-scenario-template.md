# Карточка приёмки сценария

Скопировать для конкретного изменённого сценария до начала проверки.

- ID / область / границы проверки:
- Риск и причина приоритета:
- Ответственный за исправление / ответственный за проверку:
- Полный SHA чистой сборки либо SHA базы + patch/hash-манифест:
- URL / версия / окружение / браузер и ОС / роль / реальные или подменённые данные:
- Версии Искры (ПК / iPhone / iPad / Android, см. docs/platforms.md): какие проверены и как (превью / симулятор / устройство), какие нет:
- Данные A/B с одинаковым количеством и разными ID; 0/1/много/overflow; статусы:
- Требование / независимый ожидаемый результат / инварианты:

| Элемент | Исходное состояние → действие → итог | Ожидаемые IDs/эффект | Размер/тема/ввод | Факт | Доказательство | Статус |
|---|---|---|---|---|---|---|
| Заполнить все кнопки, ссылки, строки, жесты, возврат и закрытие | Обычный, повторный, быстрый, обратный путь | Проверять результат, а не только активный стиль | Обязательная матрица ui-rules | | | NOT TESTED |

| Временной сценарий | Контролируемое событие | Что нельзя нарушить | Факт / доказательство |
|---|---|---|---|
| A → B, A отвечает позже | Задержать A, завершить B, доставить A | Содержимое B не подменяется | |
| Ошибка / повтор / закрытие в процессе | Контролируемый отказ/таймаут | Черновик и корректный выбор сохраняются; нет позднего побочного эффекта | |
| Двойное действие / обрыв после сохранения | Повторить запрос/клик | Нет дубля или потери результата | |
| Первый кадр и весь переход | Наблюдение до клика и после окончания | Нет старых данных под новой подписью, наложений, исчезновения и недоступных целей | |

- Начало/середина/конец каждого overflow, включая горизонтальный:
- Фокус, клавиатура, Escape, zoom, размеры целей, читаемость и контраст:
- Reload / свежая сессия / другой участник / сверка серверного результата:
- Намеренно возвращённый дефект и результат проверки самого теста:
- Необработанные ошибки UI/консоли/сети:
- Изменялись ли исходники/данные во время прогона:
- Найденные дефекты и регрессии:
- Непокрытые обязательные комбинации и причина:
- Заключение отдельно по логике / fixture UI / E2E / движению / устройствам:

PASS — только для перечисленной подтверждённой области. PARTIAL — есть
непокрытые обязательные клетки; FAIL — наблюдаемое расхождение; BLOCKED —
проверке мешает конкретное условие. Неприменимость требует объяснения.

## OAuth после появившегося исправления

Актуальный socialAuth.ts теперь отслеживает browserFinished, даёт 750 мс на callback и защищает обмен от гонки с закрытием. SocialLoginButtons слушает auth-cancelled. Этот продуктовый патч выполнен вне текущего прогона; здесь проведена независимая повторная проверка.

`node scripts/checkSocialAuthRecovery.mjs` — PASS: отмена native browser, гонка закрытия с PKCE callback, успешный вход и cleanup при ошибке старта. Мокируются Auth и native API; это не реальный Apple/iPhone.

`ISKRA_QA_OUTPUT=docs/qa/readiness-2026-11-03/interrupted-login-followup node scripts/checkInterruptedSocialLogin.mjs` — 2 PASS / 2 FAIL:

- Закрытие native browser без callback → обе кнопки доступны, роль pending удалена: PASS.
- Browser.open отклонил promise → обе кнопки доступны, pending удалён: PASS.
- Browser.open не завершается, 120 секунд → кнопки заблокированы, отдельной отмены в компоненте нет: FAIL критерия доступного выхода. Это проверка компонента: наличие выхода на родительском экране на настоящем устройстве ещё не проверено.
- Через 181 секунду таймаут возвращает кнопки, но iskra:oauth-role остаётся teacher: FAIL cleanup. Не утверждаем, что после таймаута кнопки остаются заблокированными.

Результаты и снимки — interrupted-login-followup/. Границы моков указаны в JSON. Исходный iPhone-кейс логически исправлен для события browserFinished, но проверка соответствующей установленной сборки на iPhone остаётся.

Во время этого этапа свободное место колебалось 5.3 → 3.8 GiB. Подготовлен список 25 временных worktree node_modules (~9.08 GiB), не использовавшихся обнаруженными процессами в момент проверки. Это только кандидаты для согласованной очистки; ничего не удалено. Удаление требует повторной проверки процессов/cwd и запрета симлинков. Список — cleanup-candidates.json. Сохранять исходники, .git, lockfiles и все QA-артефакты.

Не подключаться к чужому dev server на 5291 для приёмки: режим DEV может обходить авторизацию; использовать согласованный отдельный port и замороженную production-сборку.

## Отказ провайдера

Расширенный тест interrupted-login-expanded/ даёт 2 PASS / 3 FAIL. При callback error=access_denied управление и pending intent восстанавливаются, но Alert показывает буквальный технический код access_denied вместо понятной отмены. Тест ожидает завершения fire-and-forget native callback и React перед проверкой DOM, чтобы не принимать промежуточный рендер за дефект.

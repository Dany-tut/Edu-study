# Мини-виджет шапки Искры: возврат с главной

Причина: `DashboardPage` условно удаляет desktop-шапку на главной и телефоне.
Эффект позиционирования зависел только от `pillMounted`. После первого показа
это значение оставалось `true`; новый контейнер получал `left: 0`, а эффект
продолжал наблюдать прежний DOM. Более того, сохранённое `last` запрещало
повторную запись координаты при неизменном крае меню.

Воспроизведение: открыть дневник → главную → подождать больше 800 мс → дневник.
Исходный компонент в браузере: `widget left=0, nav right=885.8984375`.
Лог падения той же регрессионной проверки: `before.log`.

Исправление: мини-виджет занимает правую колонку существующей симметричной
сетки шапки с отступом 20 px. Позиция больше не зависит от React-эффекта,
ResizeObserver и времени перехода. Ширина ограничена свободным местом.

Проверка: `npm run check:student-topbar` при работающем локальном Vite.
Нужен Playwright (путь можно задать `ISKRA_PLAYWRIGHT_MODULE`); браузер — Chrome
либо `ISKRA_BROWSER_CHANNEL=chromium`, либо `ISKRA_CHROMIUM_PATH`.
Другой локальный порт задаётся `ISKRA_QA_ORIGIN`. Скрипт запрещает удалённый origin,
создаёт синтетическую сессию и подменяет REST-ответы пустыми списками.
Реальные данные, вход и сохранение на сервер не проверяются этим сценарием.

Пройдено 35 состояний: прямая ссылка, перезагрузка, пять возвратов с главной,
ширины 1024/1280/1440/1920, пять раскрытий/сворачиваний на каждой ширине,
телефоны 320/390 и возврат на desktop. Положение проверяется каждые 40 мс
на протяжении входной анимации; проверяются зазор, центрирование меню и граница окна.
Дополнительно просмотрены снимки начала/середины/конца прокрутки дневника
и горизонтальных фильтров на desktop и телефоне. Фейды и overflow не переносились.
Непроверенные действия: соседние режимы карусели, уведомления и управление таймером;
данное исправление меняет только внешний контейнер мини-виджета.

`npm run check:ui`, `npx tsc --noEmit`, `git diff --check` прошли.
Результаты браузера: `results.json`. Полные снимки сохраняются в
`/tmp/iskra-topbar-qa/`; CI сохраняет их артефактом `student-topbar-geometry`.

Почему прежние проверки пропускали: `check:student-widgets` покрывает состояния
карточек главной; `checkWidgetSizing` — размеры рабочего стола. В основном CI
не было проверки положения `CompactWidgetPill` после удаления и повторного
создания шапки. Теперь браузерный сценарий включён в обязательный check
«Типы, сторожа, сборка». Это объясняет пробел автоматизации; действия отдельных
ручных тестировщиков по этим данным установить нельзя.

Изменения локальные; production не выпускался.

# Проверка домашних работ через Linali

Сервер: Supabase проекта Искра `igsdwvwiqnozgwczzycx`. Функция `hw-grade-run` готовит предварительный разбор; финальное решение сохраняется обычной проверкой преподавателя. Railway для этого сценария не нужен.

## Последний шаг подключения

Открыть [Secrets Edge Functions](https://supabase.com/dashboard/project/igsdwvwiqnozgwczzycx/functions/secrets) и добавить:

- Name: `LINALI_API_KEY`
- Value: ключ из личного кабинета Linali.

Если ключ уже сохранён в `KIE_API_KEY`, его можно явно выбрать только для проверяющего настройкой `LINALI_KEY_SOURCE=KIE_API_KEY`. Автоматического использования чужого ключа нет; `LINALI_API_KEY` имеет приоритет.

Ключ не помещать в таблицы, `VITE_*`, фронтенд или репозиторий. Настройки других ИИ-функций (`AI_API_KEY`, `AI_BASE_URL`) не меняются.

`LINALI_HW_MODEL` — необязательная серверная настройка модели. По умолчанию используется `anthropic/claude-opus-5.5`, подтверждённый каталогом Linali и успешной проверкой учебного ответа. Если нужен другой движок, сначала сверить доступные идентификаторы через `GET https://api.linaliapi.com/v1/models` с ключом Linali и задать точный идентификатор. Проверяет API-модель, а не текущая сессия чата.

## Путь работы

Сдача → `hw_ai_grades` → приватный вызов функции через `pg_net` → Linali → проверка структуры результата и цитат → карточка преподавателя. Разбор появляется при открытии работы и обновляется каждые 10 секунд, пока проверка не закончена. Имена, идентификаторы ученика и пути хранилища не добавляются в запрос модели; отправляются условия, эталоны, ответы и байты фото.

Функция принимает JWT преподавателя для `start`/`retry` и отдельно проверяет владельца работы в RPC. RPC `hw_ai_grade_request` намеренно использует SECURITY DEFINER: он даёт преподавателю ограниченное право поставить собственную работу в очередь, сохраняя запрет прямой записи в таблицу для клиентов. Проверки `auth.uid()`, владельца ученика и группы находятся внутри RPC. Универсальный advisor отмечает такой подписанный RPC предупреждением; анонимный EXECUTE отозван. Фоновый `tick` принимает только существующий `HW_GRADE_SECRET`. Планировщик каждую минуту подбирает очередь, потерянные вызовы и разрешённые повторные попытки. Его URL и секрет находятся в Vault. Отправлять ответ ученику и менять итоговую оценку функция не может.

Результат сохраняется только по активной аренде задания. Пересдача, перехват задания другим исполнителем и завершение проверки преподавателем делают старый ответ неприменимым. Текст ИИ экранируется перед вставкой в HTML-редактор.

## Ошибки

Состояния сохраняются рядом с работой, без сырых сообщений провайдера. Карточка различает отсутствие/ошибку ключа, недостаток средств, лимит запросов, таймаут, временную недоступность, неполный разбор и недоступное фото. Временные ошибки допускают максимум три автоматические попытки с паузами. После этого доступен ручной повтор. Ограничение ручных повторов — 30 секунд. Ошибка проверки не уничтожает ответы, вложения и черновик преподавателя.

Для авторских заданий без числовых критериев готовится комментарий без выдуманной оценки. Процент подписан как результат заданий с критериями; итог всей работы утверждает преподаватель.

В `/journal-stand/?example=groups#/teacher/homework-review?student=example-group-0-1` есть переключатель учебных состояний. Он не вызывает платную модель и не изменяет базу.

# Карточка домашки в журнале

Обычная карточка (`HomeworkHub`) читает предоценку только для открытой реальной сдачи. Если сдача ещё ждёт проверки и задания нет в очереди ИИ, карточка запускает `hw-grade-run` под сессией преподавателя. Во время проверки результат перечитывается каждые 10 секунд; при закрытии карточки опрос прекращается. Учебные примеры запросов к провайдеру не отправляют.

Разбор появляется под соответствующим ответом, сводка — в правой панели. Замечания ИИ учитываются в фильтре «Ошибки». «Применить оценку» и «Вставить в комментарий» меняют только черновик; публикация ученику происходит через существующее сохранение проверки. Повторная сдача не наследует разбор старой попытки. Ошибка ИИ не мешает ручной проверке.

# Поправки учителя и пакетное подтверждение

Миграция `20261106120000_hw_ai_corrections_batch.sql`.

**Поправки.** Когда преподаватель утверждает проверку (`hw_ai_grade_confirm`), триггер сравнивает его итог и замечание с предоценкой и по каждому разобранному заданию сохраняет расхождение в `hw_ai_corrections`: условие, ответ, балл ИИ, балл преподавателя, комментарий. Обычное ДЗ сравнивается по итогу работы (0–100), сложное — по оценке 1–5 за задание. «Замечание» считается расхождением, если комментарий преподавателя не короче 20 знаков и не содержит комментария ИИ. Имя и фамилия ученика (с окончаниями) и почты вычищаются из текста; ID ученика в таблице нет. Условие и ответ берутся из снимка `result.inputs`, который функция сохраняет вместе с разбором, поэтому разборы до этой миграции поправок не дают.

Перед новой проверкой `hw-grade-run` берёт до четырёх последних поправок того же преподавателя по тому же предмету и экзамену: сначала то же задание (та же домашка и номер или тот же банковый ключ), затем та же линия КИМ, не больше двух на линию. Они идут в промпт блоком «Поправки этого преподавателя» перед заданиями (`pickCorrections`, `correctionsBlock` в `grader.ts`). Сколько примеров ушло, видно в `result.corrections_used`. Рубильник — флаг `ai_hw_learn`; выключение убирает примеры, сохранение поправок продолжается.

Сводка для преподавателя — кнопка «Где ИИ расходится с вами» над очередью «Нужно проверить»: совпало / ИИ завысил / занизил / только замечание за 90 дней и линии КИМ с наибольшим числом поправок (`AiAgreementPanel`, сетка `QuadrantGrid` из `CalibrationMatrix`).

**Пакет.** «Применить все уверенные» в очереди. Модель не сообщает уверенность, поэтому порог строится по тому, что реально возвращает grader. Работа уверенная, если это обычное ДЗ с баллом, у каждого задания КИМ все элементы — «есть» с найденной в ответе цитатой или «нет», нет «частично», нет цитат с фото (код засчитывает их без сверки), нет авторских заданий с разбором (их оценивает преподаватель) и задание не на линии, где преподаватель за 60 дней дважды поправлял балл. Логика одна — `iskra_private.hw_ai_grade_doubt`; `hw_ai_grade_batch_preview()` показывает, что применится и почему остальные спорные. Перед применением — подтверждение с числом работ и причинами, затем 8 секунд на отмену: до конца отсчёта в базу ничего не пишется. `hw_ai_grade_apply_batch(ids)` перепроверяет каждую работу (владелец, уверенность, работа всё ещё ждёт проверки, та же попытка) и записывает её как обычную проверку: `completed`, балл ИИ, комментарий ИИ от имени преподавателя; предоценка — `confirmed`. Сложные задания пакетом не применяются.

На реальных данных 6.11.2026 из трёх готовых предоценок уверенной была одна (только «есть»/«нет»), одна — с «частично», одна — по фото.

# Проверка домашних работ через Linali

Сервер: Supabase проекта Искра `igsdwvwiqnozgwczzycx`. Функция `hw-grade-run` готовит предварительный разбор; финальное решение сохраняется обычной проверкой преподавателя. Railway для этого сценария не нужен.

## Последний шаг подключения

Открыть [Secrets Edge Functions](https://supabase.com/dashboard/project/igsdwvwiqnozgwczzycx/functions/secrets) и добавить:

- Name: `LINALI_API_KEY`
- Value: ключ из личного кабинета Linali.

Ключ не помещать в таблицы, `VITE_*`, фронтенд или репозиторий. Настройки других ИИ-функций (`AI_API_KEY`, `AI_BASE_URL`) не меняются.

`LINALI_HW_MODEL` — необязательная серверная настройка модели. По умолчанию используется `anthropic/claude-opus-5`, указанный в [примере Linali](https://linaliapi.com/). Если нужен другой движок, сначала сверить доступные идентификаторы через `GET https://api.linaliapi.com/v1/models` с ключом Linali и задать точный идентификатор. Проверяет API-модель, а не текущая сессия чата.

## Путь работы

Сдача → `hw_ai_grades` → приватный вызов функции через `pg_net` → Linali → проверка структуры результата и цитат → карточка преподавателя. Разбор появляется при открытии работы и обновляется каждые 10 секунд, пока проверка не закончена. Имена, идентификаторы ученика и пути хранилища не добавляются в запрос модели; отправляются условия, эталоны, ответы и байты фото.

Функция принимает JWT преподавателя для `start`/`retry` и отдельно проверяет владельца работы в RPC. RPC `hw_ai_grade_request` намеренно использует SECURITY DEFINER: он даёт преподавателю ограниченное право поставить собственную работу в очередь, сохраняя запрет прямой записи в таблицу для клиентов. Проверки `auth.uid()`, владельца ученика и группы находятся внутри RPC. Универсальный advisor отмечает такой подписанный RPC предупреждением; анонимный EXECUTE отозван. Фоновый `tick` принимает только существующий `HW_GRADE_SECRET`. Планировщик каждую минуту подбирает очередь, потерянные вызовы и разрешённые повторные попытки. Его URL и секрет находятся в Vault. Отправлять ответ ученику и менять итоговую оценку функция не может.

Результат сохраняется только по активной аренде задания. Пересдача, перехват задания другим исполнителем и завершение проверки преподавателем делают старый ответ неприменимым. Текст ИИ экранируется перед вставкой в HTML-редактор.

## Ошибки

Состояния сохраняются рядом с работой, без сырых сообщений провайдера. Карточка различает отсутствие/ошибку ключа, недостаток средств, лимит запросов, таймаут, временную недоступность, неполный разбор и недоступное фото. Временные ошибки допускают максимум три автоматические попытки с паузами. После этого доступен ручной повтор. Ограничение ручных повторов — 30 секунд. Ошибка проверки не уничтожает ответы, вложения и черновик преподавателя.

Для авторских заданий без числовых критериев готовится комментарий без выдуманной оценки. Процент подписан как результат заданий с критериями; итог всей работы утверждает преподаватель.

В `/journal-stand/?example=groups#/teacher/homework-review?student=example-group-0-1` есть переключатель учебных состояний. Он не вызывает платную модель и не изменяет базу.

## Проверки

- `deno check --node-modules-dir=none supabase/functions/hw-grade-run/index.ts supabase/functions/hw-grade/index.ts`
- `deno test --node-modules-dir=none supabase/functions/_shared/homeworkAi_test.ts supabase/functions/_shared/homeworkImage_test.ts`
- `npm exec tsc -- --noEmit`

После добавления ключа проверить одну реальную сдачу: `pending → working → graded`, комментарий по каждому заданию и применение оценки. До добавления ключа подтверждена инфраструктура, но реальный ответ Linali не проверен.

# Искра · редизайн 19 виджетов

Предложение на основе production-кода 6b8d3d0d. Это концепт, а не изменение рабочего приложения. Все взаимодействия с данными имитируются локально; запросов и сохранений в базе нет.

## Сетка

Общая дискретная геометрия deskWidgetSizing: 8 колонок на 1440 и 1920 px, 4 на 1280 px, промежуток 8 px. Эталон 1440×900: клетка 165×120 px. Для каждой карточки — **явный список пар**, не диапазон min/max. 1×1 не означает квадрат в пикселях. На маленьком экране каталог показывает эталонные карточки с горизонтальной прокруткой и фейдами, не сжимает их как картинку.

Для приложения на телефоне нужен отдельный одноколоночный режим по ширине окна: исходная клеточная раскладка десктопа сохраняется, порядок стабилен; основные действия доступны без hover. Концепт не выдаёт горизонтально прокручиваемый эталонный стол за готовый мобильный экран приложения.

## Данные и ограничения

Имена, группы и занятия взяты из teacherDevDemo / teacherHomeDemo. Их значения — разные демонстрационные срезы, не отчёт аккаунта. Платежи, задачи и причины напоминаний представлены отдельными примерами существующих схем, не реальными операциями и не новыми серверными полями. Визуальные суммы/сроки этих строк не следует переносить в сиды production. Нет выдуманных трендов, конверсий или процентов прогноза.

useFinanceSummary сейчас возвращает начальные нули без loading/error: перед реализацией добавить состояние запроса, не показывать 0 до успешного RPC. useAllStudents и useGroups также должны явно передавать загрузку/ошибку в общий адаптер. Отсутствующее поле — «нет данных», а не ноль. Не менять формулы во время визуального редизайна без согласования определений.

## Состояния и действия

В стенде доступны данные / пусто / загрузка / ошибка / длинный текст, темы и три эталонных экрана. Шапка и подвал не прокручиваются вместе со списком. Фейды зависят от фактического переполнения: начало — дальний край; середина — оба; конец — начальный; помещающийся контент — без маски. Заголовки и значения переносятся, основной контент не скрывается по брейкпоинту. Если контент не влезает, прокручивается только содержимое.

3D: использованы существующие ассеты Искры из widget-objects-v2-shadows и schedule-objects-v2-shadows. Широкие показатели 2×1, крупные напоминания и пустые состояния; отключаются переключателем. Они не заменяют данные, не являются графиком и не растягивают метрики. Для студентов, карточек учеников и четырёх финансовых показателей сгенерированы шесть отдельных PNG с прозрачностью. ДЗ — блокнот; уроки — часы; студенты — группа людей; карточки учеников — ID-карточки; получено — кошелёк с галочкой; ожидается — платёж с песочными часами; долг — счёт с предупреждением; прогноз — календарь с прозрачной сферой. Соответствия хранятся в objects.ts; общего запасного рисунка нет.

## Перенос в приложение после согласования

1. Перенести catalog.sizes в единый allowedSizes-реестр. Сетка, ручки изменения, галерея, добавление и стенд читают один источник. Ограничение минимальной ширины текста — дополнительная проверка в пикселях; оно не разрешает произвольные дробные размеры.
2. При drag/resize выбирать ближайшую разрешённую пару. Превью до отпускания показывает итоговую пару, запретные пары недоступны. Сохранять ручные пустые строки.
3. При миграции старой большой метрики выбрать ближайший полезный размер и сохранить её координаты; перед применением показать пользователю, какие карточки переместятся при пересечении. Не сбрасывать весь стол.
4. Три legacy-сводки разложить на независимые metric-id с сохранением порядка и прав доступа. Дубликаты не добавлять.
5. Один адаптер модели на стол вместо отдельного запроса для каждой копии виджета. Повторно использовать sharedQuery / текущие хуки, owner scope и правила доступа. Новые backend-поля для этого концепта не требуются. Недельный календарь использует useTeacherWeek; не создавать события из данных повестки дня.
6. Все текущие действия подключаются к существующим store-методам/редакторам. Платёж — текущий addPayment с проверкой суммы, состоянием saving/error и защитой от повторов; ошибка не превращается в «оплачено». Новые стрелки-переходы в метриках и истории — предложения навигации, а не существующие действия.
7. При реализации каждый набор проверяется на коротких/длинных данных, малом и большом экране, начало/середина/конец скролла, без переполнения шапок и значений. Недоступные и скрытые виджеты не раскрывать через галерею или стенд.

## По каждому виджету

### Студентов · stat-students

- Размеры: **1×1, 2×1**.
- Источник: useHomeData → useAllStudents / useGroups.
- Поля: totalStudents, groups.length.
- Действия: Сейчас карточка информационная. Переход в раздел — предлагаемое действие, без новой записи данных.
- Адаптация: 1×1: число и название. 2×1: число + количество групп. Выше одной строки не растёт.
- Уточнение: totalStudents дедуплицирует personId / authUserId / id. Не заменять длиной массива карточек.

### Должники · finance-overdue

- Размеры: **2×2, 3×2, 3×3, 4×3, 4×4**.
- Источник: useAllStudents + useGroups; addPayment.
- Поля: name, groupId, lessonBalance, debt, paymentDue, paymentAmount; paidIds, paying.
- Действия: Все → финансы; «Оплачено» → addPayment. Сумма и состояние запроса видны; повторный клик блокируется.
- Адаптация: 2×2: имя, сумма, срок и действие в две строки. 3×2: группа и причина. 3×3: больше строк. 4×3: выровненные столбцы. 4×4: больше учеников одновременно, те же действия.
- Уточнение: Сейчас фильтр включает любую paymentDue, даже будущую. Заголовок «Должники» требует уточнения фильтра. paymentAmount — сумма платежа, не обязательно debt.

### История платежей · finance-activity

- Размеры: **2×2, 3×2, 3×3, 4×3, 4×4**.
- Источник: usePayments → payments + useAllStudents.
- Поля: studentId, amount, lessonsPaid, note, paidAt; student.name.
- Действия: Текущий виджет только читает историю. Предлагаемый переход «Все платежи» — в существующий раздел финансов.
- Адаптация: 2×2: имя, сумма, дата. 3×2: число оплаченных занятий и заметка. 3×3: больше строк. 4×3: полная строка таблицы. 4×4: больше платежей без увеличения строк.

- Уточнение: Текущий список ограничен первыми 8 записями. Для полной очереди нужен отдельный экран; нельзя показывать 8 как общее количество.

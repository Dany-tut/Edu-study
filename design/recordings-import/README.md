Статус: хранилище — **вариант A утверждён Дани 24.11.2026**; кеш для РФ поднят.
Концепт UI **согласован Дани 24.11** (A, B, C); правка: статус на модуле компактный —
облачко у урока, подпись при наведении/нажатии. Плеер берёт R2 через кеш — e968bea8.
Концепт экранов: `design/recordings-import/concept.html` (4 версии × 2 темы).

## Что получает учитель

1. На модуле курса — пункт «Папка с записями». Вставляет ссылку на публичную
   папку Google Диска или Яндекс Диска («Водоросли» → «Водоросли 1», «Водоросли 2»…).
2. Искра сама читает папку и показывает таблицу «файл → урок» с пометкой,
   по чему сопоставлено: номер в имени, название или порядок.
3. Учитель подтверждает (может снять галочку, перекинуть файл на другой урок).
4. Ролики копируются в наше хранилище; ссылка в уроке ставится сама. В модуле
   виден прогресс «Копируем 2 из 6 · 1,1 ГБ».
5. Новые файлы в папке: кнопка «Подтянуть записи» и автоматическая проверка раз
   в 3 часа. Если урок пуст и совпадение уверенное — запись ставится сама.
   Иначе на модуле появляется «2 записи ждут подтверждения».

## Кеш для РФ — поднят 24.11.2026

DNS зоны `iskra-study.ru` у Timeweb, записи `media.` нет, поэтому кеш висит на уже
рабочем адресе: **`https://api.iskra-study.ru/media/<ключ в R2>`** → `r2.dev`.
Отдельный `media.` — по желанию позже (A-запись в панели Timeweb + certbot).

- `/etc/nginx/conf.d/iskra-media-cache.conf` — `proxy_cache_path … max_size=5g min_free=1g inactive=30d`.
- `/etc/nginx/snippets/iskra-media.conf` — `location /media/`: только GET/HEAD,
  `slice 4m`, ключ `$uri$slice_range`, `Access-Control-Allow-Origin: *`,
  заголовок `X-Iskra-Cache` (MISS/HIT). Подключён в `sites-available/api.iskra-study.ru`
  перед `location /`. Копия прежнего конфига — `/root/api.iskra-study.ru.bak-*`.
- Проверено: диапазон 1 МБ из середины — MISS, затем HIT, байты совпадают с `r2.dev`;
  HEAD 200 с полной длиной и `accept-ranges`; POST → 403; несуществующий → 404;
  прокси Supabase не задет. С Mac (RTT 0,27 с) ≈ 3,5 МБ/с ≈ 28 Мбит/с.
- Диск: кеш ограничен 5 ГБ, пока диск VPS не расширен до ~50 ГБ (тогда `max_size=40g`).

## Где идёт копирование — на VPS, не в Supabase и не в Worker

Служба `iskra-media-sync` (systemd) на том же VPS:

- Скачивает поток с Диска и тут же заливает в R2 многочастной загрузкой
  (`rclone`, части по 16 МБ, ≈ 64 МБ памяти). Файл на диск VPS не пишется.
- Supabase видит только маленькие запросы: прочитать очередь, записать статус,
  вызвать RPC подстановки ссылки. Видео через Supabase не проходит вообще.
- Почему не Cloudflare Worker: нужен вход wrangler (OAuth Дани), Google часто
  отвечает 429 на адреса Cloudflare, у Worker ограничено время. VPS уже наш,
  с нужной сетью и nginx.

Листинг папок:
- Яндекс: `GET cloud-api.yandex.net/v1/disk/public/resources?public_key=<url>&limit=200`,
  без ключа; скачивание — `…/public/resources/download?public_key=…&path=…` → `href`.
- Google: Drive API v3 `files?q='<folderId>' in parents and trashed=false&key=<API_KEY>`
  (ключ ограничен Drive API и только этим VPS); скачивание —
  `drive.usercontent.google.com/download?id=…&export=download&confirm=t`.
  «Превышена квота скачивания» у Google → повтор через час, статус в UI.
- Вложенные папки — один уровень вглубь. Видео-файлы: mp4, m4v, mov, webm.
  mkv/avi: перепаковка `ffmpeg -c copy` в mp4 (без перекодирования) — этап 2.
- Принимаются только ссылки `drive.google.com`, `disk.yandex.ru|com`, `yadi.sk`
  (никакого произвольного адреса — защита от SSRF).

Интерфейс сканирования: браузер учителя → `https://api.iskra-study.ru/media/scan`
(новый location на том же nginx, проксирует на службу). Служба проверяет JWT
учителя у Supabase Auth и права на модуль запросом с его же токеном (RLS).

## Сопоставление файлов с уроками

Уроки модуля по порядку (`position`). Для каждого файла, по приоритету:
1. **Номер**: последнее число в имени (`Водоросли 2`, `02_водоросли`, `урок 2`,
   `Занятие №2`) → 2-й урок модуля; если в курсе сквозная нумерация и число
   совпадает с `lesson_number` — по нему. Даты (`2026-11-03`) не считаются номером.
2. **Название**: совпадение слов имени файла и названия урока ≥ 60 %.
3. **Порядок**: естественная сортировка имён → уроки по порядку.

Каждой паре — метка «по номеру / по названию / по порядку». Дубли (два файла на
один урок) и лишние файлы (уроков меньше) — красным, по умолчанию не отмечены.

## Данные (протокол `docs/data-preservation.md`)

Новые таблицы (автоматически попадают под `iskra_history` и в бэкап):

- `course_module_recording_sources` — `module_id`, `provider` (gdrive|yadisk),
  `folder_url`, `folder_ref`, `auto_sync`, `last_scan_at`, `last_error`, `created_by`.
- `recording_import_items` — `source_id`, `lesson_id`, `provider_file_id`,
  `file_name`, `size_bytes`, `provider_checksum`, `match_kind`, `status`
  (proposed → confirmed → copying → copied → applied | conflict | failed | skipped),
  `r2_key`, `media_url`, `expected_old_url`, `old_chapter_source`, `error`.
  **unique (source_id, provider_file_id)** — повторный запуск видит только новые файлы.

Подстановка ссылки — RPC `apply_recording_import(item_id)` (security definer, только
служба), одна транзакция:
1. `select … for update` урока; `youtube_url IS NOT DISTINCT FROM expected_old_url`,
   иначе статус `conflict` — учитель поменял ссылку сам, ничего не пишем.
2. `update lessons set youtube_url = media_url` — только это поле. В
   `chapter_variants` меняется только `source`, равный старой ссылке.
3. Старое значение остаётся в `recording_import_items` и в `iskra_history.row_versions`
   → адресный откат одной кнопкой «Вернуть прежнюю ссылку».

Урок, где уже стоит ссылка (YouTube, RuTube, Диск): в таблице по умолчанию
**не отмечен**, рядом видна текущая ссылка; заменить можно только явной галочкой.
Автосинхронизация такие уроки никогда не трогает.

Ключ в R2: `rec/<course_short_id>/<lesson_short_id>-<fileId8>.<ext>`; ссылка в
уроке — `https://api.iskra-study.ru/media/rec/…` (тип `file` → наш плеер, до 10×).
Плеер: при ошибке сети на кеше повторяет тот же путь с `r2.dev`.

Искра · Концепт «Итоги урока из расшифровки»

Схема данных и промпт

Черновик для обсуждения, не реализация. Общий для всех трёх вариантов интерфейса: варианты отличаются экраном, а не тем, где лежат данные.

Поток

  1. Учитель нажимает кнопку → клиент вызывает Edge Function lesson-recap с lesson_id и списком нужных видов (kinds).
  2. Функция проверяет: флаги ai_enabled + ai_lesson_recap (иначе 409 и кнопки нет вовсе), владельца урока, наличие lessons.content.transcript, дневной лимит учителя.
  3. Расшифровка собирается в нумерованные реплики, имена заменяются на «Учитель / Ученик А» (наружу не уходят ни имена, ни видео).
  4. Один вызов модели со структурированным ответом (JSON-схема). Каждый пункт ссылается на номера реплик, а не на время: таймкоды считает сервер по сегментам, модель их не придумывает.
  5. Сервер проверяет ответ (номера реплик в диапазоне, пустые пункты выкинуты, длины), пишет черновик в lesson_recaps со статусом ready. В урок ничего не попадает.
  6. Учитель правит черновик на месте → «Опубликовать» / «Применить» / «Принять». Раскладку делает клиент существующими путями сохранения урока, ДЗ и карточек — те же права, те же проверки.

Почему черновик не в lessons.content: ученик загружает content целиком (src/lib/db.ts, выборка short_id, content, homework). Всё, что лежит там, уже у него в браузере, даже если интерфейс это прячет. Черновик и особенно заметка о том, где ученик путался, должны жить в таблице, которую RLS отдаёт только владельцу урока.

Черновик: тип RecapDraft

type Src = number[]                       // номера реплик расшифровки; время считает сервер
interface RecapDraft {
  lang: string                            // язык урока, для карточек и озвучки
  summary?:   { title: string; text: string; src: Src; off?: boolean }[]          // 3–6 абзацев
  questions?: { q: string; answer: string; kind: 'choice' | 'short';
                options?: string[]; src: Src; off?: boolean }[]                   // 5–10
  cards?:     { term: string; meaning: string; note?: string; src: Src; off?: boolean }[]
  hw?: { title: string;
         tasks: { title: string; type: 'shortAnswer' | 'choice' | 'text';
                  items: string[]; src: Src; off?: boolean }[] }                 // типы — из существующих заданий
  note?: { kind: 'confusion' | 'question' | 'strength' | 'not_covered';
           text: string; count?: number; src: Src; off?: boolean }[]
}

off — снятая учителем галочка: пункт остаётся в черновике (можно вернуть), но не публикуется. Правки учителя перезаписывают текст в draft; при «Пересобрать раздел» правленые пункты не трогаются без подтверждения.

Промпт (черновик)

Системная часть

Ты помогаешь преподавателю подвести итоги проведённого урока по его расшифровке.
Расшифровка — единственный источник. Не добавляй фактов, правил, примеров и терминов,
которых не было на уроке, даже если они верные. Если на уроке что-то сказано неточно,
не исправляй молча — отметь это в заметке учителю (kind: "question").

Реплики пронумерованы: [12] 07:30 Учитель: … Ссылайся на них полем src — только
номерами, которые есть во входе. Каждый пункт обязан иметь хотя бы одну ссылку.

Что собрать (только перечисленные в kinds):
- summary: 3–6 коротких абзацев для ученика и для тех, кто пропустил. Заголовок — суть
  абзаца. Пиши просто, на «вы» не обращайся, без вступлений «На уроке мы…».
- questions: 5–10 вопросов на понимание того, что прозвучало. Ответ однозначный.
  Вопрос не содержит ответа. Для choice — 3 варианта, один верный, неверные взяты из
  реальных ошибок на уроке, если они были.
- cards: термины и выражения урока, по одному значению на карточку, в форме, в которой
  их давал учитель. Не больше 12.
- hw: 2–4 задания только по пройденному. Типы — shortAnswer, choice, text.
  Не повторяй вопросы из questions дословно.
- note: для преподавателя. Где ученик ошибался (с числом повторов), что спрашивал,
  что получилось уверенно, что не успели. Без оценок личности и без советов «больше
  стараться». Это видит только преподаватель.

Язык ответа — русский; термины изучаемого языка — как в расшифровке.
Ответ — строго по JSON-схеме.

Пользовательская часть

Курс: Корейский с нуля. Урок 5: «Который час». Предмет: korean.
Уже есть в уроке (не дублируй): «Числа до ста: повторение», «Который час: диалог».
kinds: ["summary","questions","cards","hw","note"]

[0] 00:00 Учитель: Добрый день! Сегодня учимся говорить, который час…
[1] 04:12 Учитель: Часы мы называем родными числами — 한 시, 두 시, 세 시…
[2] 05:20 Ученик А: Тогда в час — 일 시?
…

Вызов: общий languageAiConfig из supabase/functions/_shared/languageAi.ts (Linali → kie.ai, как у cards-extract), структурированный ответ по JSON-схеме, усилие low: задача — пересказ без развилок; так же сделали перевод ленты. Ошибки показываются учителю через languageAiUserMessage, без сырых ответов провайдера (ALERT-01).

Для химии и биологии правило «только из расшифровки» особенно важно: модель не дописывает «правильную» теорию сверх сказанного на уроке.

Сколько стоит

Урок 45 минут ≈ 5–6 тыс. слов ≈ 15 тыс. входных токенов вместе с инструкцией. Ответ на все пять видов ≈ 4 тыс. токенов плюс рассуждение на усилии low ≈ 2–3 тыс. Цены — прямые цены Anthropic за 1 млн токенов; у Linali / kie.ai свои ставки, их нужно сверить с кабинетом провайдера.

В макетах указано «≈ 10 ₽» — это оценка для Sonnet 5.5. «Пересобрать раздел» отправляет ту же расшифровку и просит один вид, ответ короче — примерно половина цены. Повторное нажатие по той же расшифровке без изменений отдаёт сохранённый черновик (transcript_hash), денег не тратит.

Доступ, рубильник и ограничения

Функция работает, только если сходятся три условия. Проверяет и клиент (скрывает кнопки), и сама функция lesson-recap (отвечает 403/409).

  1. Доступ учителя — общий механизм доступа к автоматизациям (делается в основной сессии), фича-ключ lesson_recap. Админ выдаёт его конкретному учителю или всем. Без доступа учитель не видит ни кнопки во вкладке «Запись» и в монтаже, ни пункта в «Настройках».
  2. Переключатель учителя — «Настройки → Автоматизации → Итоги урока из записи». Виден только при доступе. Выключен — кнопки скрыты, сохранённые черновики и заметки не удаляются.
  3. Деньги — общий рубильник ai_enabled и ai_lesson_recap в app_flags. Выключено — функцию никто не видит, даже при доступе.
  • Порядок проверок в функции: флаги ai_* (409) → доступ lesson_recap и переключатель учителя (403) → владелец урока → лимит. Таблицы и форму хранения доступа задаёт общий механизм, здесь их не дублируем. База не отвечает — считаем выключенным.
  • Лимит: 20 сборок на учителя в сутки, счёт по lesson_recaps.created_at. Расход по каждой сборке пишется в input_tokens / output_tokens / cost_usd, их же может показывать блок аналитики.
  • Приватность: имена заменены на «Ученик А», видео и голос не отправляются. Заметка учителю хранится отдельно от урока под RLS владельца.
  • Публикация только руками: функция не пишет в lessons, card_sets и ДЗ. Раскладывает клиент по нажатию учителя, существующими путями сохранения.

Открытые вопросы к Дани

  • Групповой урок: заметка одна на группу или по пункту на каждого говорившего ученика? В схеме допускается и то и другое (student_id null).
  • «Проверь себя» засчитывается в прогресс урока или остаётся без оценки, как в макетах?
  • Уведомлять ли учеников «Итоги урока готовы» отдельно от публикации урока?

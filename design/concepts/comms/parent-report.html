Пятничная пачка: каждый отчёт Вариант A

В пятницу ИИ готовит черновики. Учитель проходит их по одному: цифры, две фразы и «Утвердить → следующий». На ПК это клавиатура, на телефоне — стопка карточек. Родитель получает весь отчёт текстом в Telegram в воскресенье в 18:00 и ссылку на подробности.

Утвердить всё, кроме отмеченных Вариант B

ИИ сам отмечает отчёты, где нужен взгляд учителя: резкое падение, пропуски, мало данных. Остальные утверждаются одной кнопкой. У родителя одна постоянная ссылка на страницу с историей недель; Telegram по желанию, подписка прямо с этой страницы.

Итог: утвердить пачкой, доставить текстом Выбран

Учитель утверждает как в B: отмеченные ИИ отчёты открывает сам, остальные — одной кнопкой. Первые две недели все отчёты помечены «на проверку», пока учитель не привыкнет к флагам. Родитель с Telegram получает отчёт целиком в сообщении, как в A. На главной — новый виджет «Отчёты родителям» из библиотеки: ставится на любой стол, в пятницу показывает «10 готовы · 2 решить» и кнопку утверждения. У каждого родителя есть и постоянная ссылка с историей недель (B): её можно переслать в любой мессенджер, оттуда же подписаться на Telegram.

Итог: что взяли из A и B

  • Утверждение — B: таблица «Требуют внимания / Все», флаги по правилам (пропуски ≥ 2, падение ≥ 15 п.п., мало данных, новый ученик), кнопка «Утвердить N». На телефоне — список исключений и одна кнопка. Первые 2 недели у учителя флаг review_all: все отчёты помечены.
  • Доставка — A + B: если родитель подключил бота — весь текст отчёта в Telegram с кнопкой «Подробнее»; если нет — учитель один раз пересылает постоянную ссылку /r/<токен>, на странице история недель и кнопка «Получать в Telegram».
  • Не берём: обязательный просмотр каждого отчёта по одному (A) — стопка остаётся доступной по «Все» для тех, кто хочет проверить всё.
  • Данные: report_links.scope = 'student' (постоянная), parent_reports.flags + teacher.preferences.reports_review_all_until.

Зачем

Родитель платит и хочет понимать, что происходит, но аккаунта в Искре у него нет и не будет. Сейчас учитель пишет родителям вручную или не пишет вовсе. Задача — раз в неделю отправить короткий честный итог, потратив на всю пачку не больше 5–10 минут. ИИ пишет фразы, но публикует их только учитель (правило AI-01: «итог публикует преподаватель»).

Рекомендация: утверждение из B (исключения + одна кнопка) с обязательным просмотром отмеченных; доставка из A (весь отчёт текстом в Telegram — его прочтут) плюс постоянная ссылка из B для тех, у кого нет Telegram. Первые 2 недели показывать учителю все отчёты (как в A), пока он не начнёт доверять флагам.

Что делает ИИ и где граница

  • На вход — только факты недели: посещаемость, статусы и баллы ДЗ, тесты, комментарии учителя к работам. Никаких оценок личности и сравнений с другими учениками по имени.
  • Две фразы по 1–2 предложения: «Получается» и «Работаем над». Каждая обязана ссылаться на факт («тест 12 из 15»). Строка «Основано на» показывает источники.
  • Флаги (B) ставит не ИИ, а правило: пропуски ≥ 2, падение балла ≥ 15 п.п., меньше 2 событий за неделю, ученик новый (первые 2 недели). ИИ о пропусках сам не пишет — формулировку выбирает учитель.
  • Флаг ai_parent_reports в app_flags — рубильник расхода; без него учитель видит цифры и пишет фразы сам.

Черновик данных

-- Контакт родителя (общий с концептом оплат — «плательщик»)
create table student_contacts (
  id          uuid primary key default gen_random_uuid(),
  student_id  uuid not null references students(id) on delete cascade,
  role        text not null check (role in ('student','parent')),
  name        text,                       -- «мама, Ольга»
  is_payer    boolean not null default false,
  tg_chat_id  bigint,                     -- после /start p_<код>
  linked_at   timestamptz, revoked_at timestamptz
);

create table parent_reports (
  id           uuid primary key default gen_random_uuid(),
  student_id   uuid not null references students(id) on delete cascade,
  teacher_id   uuid not null references auth.users(id),
  week_start   date not null,             -- понедельник
  stats        jsonb not null,            -- {lessons:{held,attended}, hw:{given,done,late}, avg_pct, prev_avg_pct, tests:[…]}
  strengths    text, focus text,          -- текст после правки
  ai_strengths text, ai_focus text,       -- исходник ИИ (для оценки качества)
  ai_sources   jsonb,                     -- на что сослался
  flags        text[] default '{}',       -- absent_2, drop_15, thin_data, new_student
  status       text not null default 'draft' check (status in ('draft','approved','skipped','sent','failed')),
  approved_at  timestamptz, sent_at timestamptz,
  unique (student_id, week_start)
);

-- Ссылка без аккаунта: храним только хэш токена
create table report_links (
  token_hash  bytea primary key,          -- sha256(токен из URL /r/<токен>)
  student_id  uuid not null references students(id) on delete cascade,
  scope       text not null check (scope in ('week','student')),  -- A: неделя, B: постоянная
  report_id   uuid references parent_reports(id),
  expires_at  timestamptz,                -- A: +30 дней; B: null, отзывается вручную
  revoked_at  timestamptz,
  last_seen_at timestamptz
);
-- Чтение страницы — edge-функция parent-report (service role), без анонимного доступа к таблицам.

Cron

select cron.schedule('parent-reports-draft', '0 14 * * 5', $$ select parent_reports_build(current_date - 4) $$); -- пт 17:00 МСК: собрать цифры + ИИ
select cron.schedule('parent-reports-nudge', '0 14 * * 5', $$ select comms_enqueue_teacher_nudge('parent_reports') $$); -- пуш учителю
select cron.schedule('parent-reports-send',  '0 15 * * 0', $$ select parent_reports_enqueue_approved() $$);     -- вс 18:00 МСК → comms_outbox

Что переиспользовать

  • Посещаемость — student_schedule_attendance / lesson_attendance (триггеры on_lesson_attended, on_lesson_attendance_updated).
  • ДЗ и баллы — teacher_journal_homework_summary_v, hw_grades; статусы сдачи — lesson_progress.
  • ИИ — тот же путь, что hw-grade: edge-функция, учёт трат как в tts_spend, рубильник в app_flags.
  • Отправка — общий comms_outbox и диспетчер (см. обзор), бот — тот же, что в tg-webhook; новая ветка /start p_<код> создаёт student_contacts с ролью parent.

Открытые вопросы

  • Согласие родителя: первое сообщение бота объясняет, кто и зачем пишет. Отписка — /stop или ссылка внизу страницы.
  • Ученик 18+ — отчёт родителю только с его согласия: галочка в карточке ученика.
  • У ученика нескольких учителей — один отчёт на учителя или общий? Предлагаю на учителя: каждый утверждает только своё.

Автопилот по шаблонам Вариант A

Три шаблона с правилами: долг (через 3 дня после урока, повтор раз в неделю, не больше 3), счёт 1-го числа по проведённым урокам и сообщение при переносе или отмене. Всё уходит само. Учитель видит журнал и может выключить автопилот у конкретного ученика.

Закрытие месяца Вариант B

Раз в месяц учитель закрывает месяц на одном экране: уроки × цена, оплачено, к оплате. Проверяет и жмёт «Выставить 9 счетов». Напоминание о долге — в одно касание с готовым текстом, но не само. О переносе или отмене Искра спрашивает в тосте сразу после действия в расписании.

Итог: месяц закрывает учитель, долг — автопилот Выбран

Счёт за месяц учитель выставляет сам на экране «Закрыть месяц» (B): видит таблицу и решает спорные поздние отмены. Напоминание о долге идёт само по шаблону (A), но только после выставленного счёта и с паузой на «Я оплатила / Оплачу до…». Отменить урок можно двумя путями: шторка из «Моего дня» с текстом для плательщика (A) или тост после жеста в расписании (B). На столе «Финансы» — новый виджет «Оплаты: ждут вас», а в «Должниках» виден статус автонапоминания; оба ставятся и убираются учителем.

Искра не принимает платежи: это список уроков и реквизиты учителя.

Счёт по ссылке, без входа. Каждый урок отдельной строкой: отменённый учителем зачёркнут, пропуск без предупреждения входит. Реквизиты задаёт учитель.

Доступ. Функция за фича-ключом payment_reminders: админ выдаёт доступ учителю или всем (Администрирование → Функции). Без доступа у учителя нет ни настроек, ни виджетов, ни строк из этого макета. С доступом — тумблер и параметры в «Настройках → Автоматизации». Подробно: Доступ к автоматизациям.

Итог: что взяли из A и B

  • Счёт — B: 1-го числа cron собирает черновики invoices (status draft); учитель получает пуш «Закрыть октябрь», видит таблицу, решает «+1?» по поздним отменам и жмёт «Выставить N счетов». В A-настройках это режим «Сначала мне».
  • Долг — A: правило +3 дня / раз в неделю / ×3 работает только по счетам со статусом sent или promised после даты обещания. «Я оплатила» ставит паузу до подтверждения учителем.
  • Отмена — оба пути: шторка «Отменить урок?» (кто отменил → текст и спишется ли урок) и тост после жеста «Сообщить маме и Маше?». Оба пишут cancelled_by и ставят сообщение в очередь с задержкой 30 с под «Отменить».
  • Не берём: ручное «Напомнить» пачкой (B) как основной путь — остаётся кнопкой в карточке ученика для внеочередного напоминания.

Зачем

Деньги — самая неловкая часть работы репетитора: напоминать о долге стыдно, считать уроки за месяц долго, а при отмене родитель спрашивает «а оплата?». Сейчас в Искре есть учёт (payments, поля payment_due/payment_amount, предоплаченные уроки) и уведомление учителю о сроке (notify_on_payment_due). Плательщику не уходит ничего.

Рекомендация: счёт — из B (раз в месяц учитель видит таблицу, особенно поздние отмены), долг — автопилот из A, но только после выставленного счёта и с паузой на «Я оплатила / Оплачу до…». Перенос и отмена — шторка из A: вопрос, кто отменил, нужен и для сообщения, и для того, спишется ли урок.

Кому уходит

Получатель — плательщик: student_contacts.is_payer (обычно родитель из концепта 5). Если плательщик не подключён к Telegram — ученику с пометкой «передай родителям», либо учителю ссылка на счёт, чтобы переслать вручную. Ученикам с предоплатой (lessons_paid, sync_prepaid_lesson_balance) вместо счёта уходит «осталось 1 оплаченное занятие».

create table invoices (
  id           uuid primary key default gen_random_uuid(),
  teacher_id   uuid not null references auth.users(id),
  student_id   uuid not null references students(id) on delete cascade,
  payer_id     uuid references student_contacts(id),

  due_date     date,
  status       text not null default 'draft' check (status in ('draft','sent','promised','paid','void')),
  promised_until date,                         -- «Оплачу до…»
  claimed_paid_at timestamptz,                 -- «Я оплатила» — ждёт подтверждения
  token_hash   bytea unique,                   -- ссылка /i/<токен>
  unique (student_id, period)
);

create table message_templates (

  body       text not null,                    -- переменные {payer} {student} {amount} {lessons} {link}

);

Что переиспользовать

  • schedule_cancel / schedule_move / schedule_undo (0121) — передавать cancelled_by; _schedule_notify ставит в очередь сообщение плательщику с ключом pay_sched:{schedule_id}:{version}, задержка 30 с под «Отменить».
  • on_payment_received — при новой записи в payments пересчитать invoices.paid, закрыть счёт, снять из очереди напоминания о долге, отправить «Оплата получена».
  • notify_on_payment_due — оставить уведомлением учителю; правило долга (A) читает те же payment_due/payment_amount для учеников без счетов.
  • sync_prepaid_lesson_balance — источник «осталось N уроков» для предоплаты.
  • Посещаемость (student_schedule_attendance) — строки счёта: был, пропуск без предупреждения, отмена.
  • В миграции 20261105120000_notifications_fixes есть ссылка на 20261105090000_payment_reminders.sql, но этого файла в ветке нет. Проверить, не делает ли его параллельная сессия, чтобы не задвоить напоминания.

Чего не делаем

  • Не принимаем деньги и не храним реквизиты карт. Только подсказка учителя («перевод по номеру»), которая показывается по нажатию.
  • Не шлём долг ночью и в выходные утром: общие тихие часы из концепта 4.

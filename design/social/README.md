# Вместе в Искре
[Четыре редактируемых состояния в Figma](https://www.figma.com/design/y8qQ23hqFJtufp7gGdZTse/?node-id=246-3). Страница 08, отдельная от Тестли. QR в концепте — демонстрационный. Вход в «Друзья» — из своего профиля; вход в комнату — из открытой викторины. Главная остаётся без прокрутки.

**Какая задача подтверждена.** В исходном обсуждении владелец продукта назвал друзей, соревнования и совместные квизы. В Искре уже есть индивидуальная викторина со стартом, таймером, ответом и итогом (QuizWidget, QuizDialogContent); результаты текущего клиента нельзя считать авторитетными для соревнования — правильный ответ доступен браузеру. Есть действительный сценарий приглашения на обучение (JoinPage), но его эффект — регистрация и привязка карточки. Это аргумент за разные входы «Учиться», «В друзья», «Играть». Для разовой игры обязательная дружба добавила бы лишнее действие. Такой вход без предварительной дружбы есть и в [официальном сценарии Kahoot](https://support.kahoot.com/hc/en-us/articles/360039890713-Kahoot-join-How-to-join-a-Kahoot-game). Это подтверждает осуществимость, а не спрос среди учеников Искры. Интервью и статистики использования социальных функций пока нет.

**Чья это карточка.** auth.users.id обозначает аккаунт. Миграция 20261102074927 создаёт profiles с серверной ролью и автоматически полученным username, потенциально из email; не публикуем его по умолчанию. students.id обозначает запись в учебном контексте; claim_student_account связывает карточки одного person_id с auth.uid(). В MobileProfilePage существует переход в кабинет преподавателя: смена кабинета не создаёт новую социальную личность. Разные аккаунты не объединяем по имени или почте. Админский просмотр чужого кабинета не должен показывать или изменять чужие социальные связи. Перед подключением UI отдельно пройти пользователя с двумя ролями и несколькими учебными карточками.

**Друзья, первый серверный срез.** Обе роли выбирают отдельный ник; связь живёт между аккаунтами. Один активный случайный UUID для одной заявки на 24 часа. Можно заменить или отозвать. Получатель входит, выбирает ник, видит ник владельца, отправляет запрос. Владелец принимает или отклоняет; отправитель может отменить, любая сторона — удалить друга. Смена ника сохраняет связь. RPC social_contact возвращает только ник, непрозрачный ID связи и её состояние либо результат конкретного действия. Нет списка пользователей, контактов телефона, групп, почты, успеваемости, рейтингов класса или прав на учебные объекты. Социальные операции не меняют RLS учебных таблиц.

**ПК · реализовано локально.** В профиле ученика и преподавателя появился вход «Друзья». Внутри доступны «Мой ник», «Поиск», «Заявки» и список друзей. Поиск включается пользователем и проверяет полное совпадение. Отзыв согласия и смена владельца ника между поиском и отправкой проверяются на сервере. Входящая заявка отображается в колокольчике и ведёт на ту же вкладку «Заявки», где её можно принять или отклонить. Открытая вкладка проверяет обновления каждые 15 секунд, при возврате в окно и при открытии колокольчика. Локальный браузерный прогон и его границы указаны в docs/qa/social-contact/desktop.md.

**План публичного запуска и следующих этапов.**
1. Подключить первый срез к интерфейсу обеих ролей на тестовом сервере. Секрет приглашения — во фрагменте URL; исключить его из аналитики, логов и referrer, возвращать на приглашение после входа. Повтор после обрыва сверяет список. Блокировка нежелательных запросов, лимиты по аккаунту, удаление социального профиля и защита от перебора свободных ников обязательны перед публичным запуском.
2. Правила точного поиска для публичного запуска. Поиск выключен по умолчанию, отдельный переключатель. Только полное совпадение нормализованного ника, без подсказок, одинаковый ответ для скрытого/отсутствующего/заблокированного, лимит запросов. Владение прежним ником не даёт связей прежнего владельца.
3. Комната — вход по ссылке, шестизначному буквенно-цифровому коду без похожих символов или приглашению другу. Код привязан только к комнате и истекает при старте/закрытии; ведущий видит ники, удаляет лишнего игрока и запускает игру. Гость видит состав только после допуска. Ограничить попытки, вместимость и время ожидания. Состояния: неверный/истёкший код, комната заполнена, ведущий вышел, переподключение в уже начатую игру. Сервер выбирает вопросы из разрешённого общего набора, хранит ключи, принимает один ответ от участника на раунд и считает итог. Ни угадывание кода, ни дружба не дают доступа к чужому курсу. Модуль Тестли не используется.
4. Соревнование — отдельное приглашение с явным согласием; рейтинг только участникам, только по результатам этой игры. Никаких оценок в журнал. Сначала проверить полезность комнаты: в небольшом пилоте дать знакомой паре добавиться по QR, другой паре — войти без дружбы по коду, ведущему — закрыть комнату. Записать успешность, время до первого вопроса, где нужна помощь и что каждый ожидал раскрыть. Расхождение ожиданий о приватности — причина изменить поток до расширения.

**Приёмка.** Карточка, воспроизводимый тест и результат — в docs/qa/social-contact. Это локальная проверка серверного контракта, не выпуск приложения.

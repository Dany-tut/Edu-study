# Видео Google Диска в плеере Искры

`POST /functions/v1/drive-video` принимает `{ fileId }` с JWT пользователя. Функция проверяет пользователя через Auth, доступ к сохранённому уроку через его RLS и публичный доступ к видео на Диске. Учитель может также проверить несохранённую ссылку. Ответ — подписанный билет на 6 часов; JWT пользователя не попадает в URL видео.

`GET` и `HEAD` с `?ticket=…` проверяют подпись и срок билета. Передаются только видео с фиксированного Google-хоста, без cookies пользователя, произвольных URL и перенаправлений. Запросы фрагментов ограничены 8 МиБ; поток не собирается целиком в памяти. Это серверный трафик Supabase, а не прямое воспроизведение из Google.

Новая функция использует стандартные серверные переменные Supabase. Для подписи билета отдельный ключ выводится из `SUPABASE_SERVICE_ROLE_KEY` с контекстом `iskra:drive-video:v1`; сервисный ключ не используется для чтения уроков. Дополнительные секреты и миграции не нужны. В `supabase/config.toml` у функции `verify_jwt = false`, поскольку GET проверяет билет, а POST проверяет JWT внутри обработчика.

Перед выпуском фронтенда развернуть `drive-video` с конфигурацией из репозитория. Фронтенд выпускать по `docs/releases.md`. Закрытые файлы, запрет скачивания или ограничения Google показывают ошибку с повтором и ссылкой на оригинал; права файла не меняются.

Проверки:

```sh
deno test --allow-env supabase/functions/_shared/driveVideo_test.ts supabase/functions/drive-video/index_test.ts
deno check supabase/functions/drive-video/index.ts
npm run check:ui
npx tsc --noEmit
npm run build
```

Плеер использует стандартный HTML video: просмотренные отрезки, сохранение позиции и порог 90% общие с обычными видео. Переход на Google Диск не засчитывает просмотр. При недоступном файле ДЗ остаётся закрытым; преподаватель должен исправить доступ или заменить ссылку. Начатые и сданные работы сохраняют доступ по общему правилу.

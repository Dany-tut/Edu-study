# Направление 9: навигация преподавателя

База: 940c88563023b79015e593a1d29225e56a7472d9. Изменения в общей изолированной рабочей копии codex/course-save-fast-20261122, без коммита/релиза этого исполнителя.

## Изменения

- TeacherConstructorPage.tsx: запускает trainers/widgets query builders сразу через Promise.resolve, до ожидания shared course IDs. Оба promise сразу имеют обработчик rejection. Карточки курса по-прежнему не ждут второстепенных каталогов.
- teacherSchedule.ts: сетевой ответ недели отделён от локальной проекции roster. Гидратация групп/учеников, новые ссылки массивов и изменение подписей повторно используют тот же ответ. Новый запрос нужен для даты, явного reload или auth scope, а не любого нового roster array.
- Ответ принадлежит точным start/auth scope; несовпадающий снимок скрывается во время render до следующего эффекта. Предыдущий запрос прерывается, его поздний ответ отвергается.
- Реальные изменения schedule/groups/students и reconnect перечитывают неделю через общий realtime transport; пачка коалесцируется за120мс. Первичный subscription SYNC не дублирует cold read.
- Сохранены фильтрация своих групп/учеников, подавление двойников, запись без времени конца, DEV/fixture путь, error/retry. Общие useGroups и область предметов не изменялись.

## Проверки

- `node qa/site-performance/navigation.mjs`: PASS. Бандлируется реальный hook; управляемый планировщик hooks и отложенные ответы проверяют число запросов при гидратации/переименовании roster, фильтрацию/двойники, смену недели, abort/late response, смену аккаунта до эффектов, отсутствие повторного запроса при token refresh того же аккаунта, failure/retry, recording, burst realtime.
- `node qa/site-performance/navigation-catalog.mjs`: PASS. Выполняется реальная функция loadAll из constructor. Отдельно удерживаются shared IDs, course query, оба каталога. Оба каталога стартуют до shared lookup; карточки показываются до завершения каталогов; rejected trainer не мешает успешному widget.
- Начальная версия изменений показала type inference union fixture/SchedItem в tsc; исправлено явным `useMemo<SchedItem[] | null>`. Итоговую единую проверку типов и release:check ведёт root; повторных сборок этим исполнителем нет.

Это проверки фактического исходного кода и topology запросов с controlled dependencies. Пользовательское время вкладок в секундах, полный UI с сервером и физические ПК/iPhone/iPad/Android этим направлением не измерены. Нет изменений внешнего вида. Финальный SHA задаст root при единой интеграции.

# Наполненный стенд календаря Искры

Запуск вручную: `npm run dev`, затем `/qa/calendar/` на локальном сервере.
Автоматическая приёмка: `npm run check:calendar-browser` сама поднимает отдельный
Vite на 5178, использует собственный кеш и закрывает сервер после проверки.
Браузер локально — Chrome; CI — установленный Playwright Chromium.
Зависимость Playwright закреплена в package-lock.json; в CI браузер устанавливается.

Реальные TeacherSchedule и WidgetTodaySchedule получают источник данных через
`useWeek`; обычное приложение использует прежний useTeacherWeek. Стенд не входит
в основной entry сборки. Фикстуры задают разные ID/подписи на каждую дату и неделю:
12 / 2 / 0 / 3 / 1 / 1 / 0 занятий, длинное имя, запись, отмена.
Стенд использует readOnly: создание, меню и перетаскивание отключены.
Автоматический прогон перехватывает запросы REST; производственные записи не нужны.
Стенд предназначен для выбора дней и недель и проверки прокрутки; операции
создания/редактирования/переноса требуют отдельного сценария и здесь не принимаются.

Приёмка проверяет содержимое карточек, а не только количество; выбранную кнопку,
подпись даты, пустой день, статусы, клавиатуру, 20 быстрых переключений, разные
недели, стрелки и Сегодня. В обеих темах используются окна 1280×820, 390×844,
320×568, 768×1024 (reduced motion), 1280×600. Для прокрутки сохраняются начало,
середина и конец и фактическая CSS-маска. Наблюдение MutationObserver и rAF начинается до клика и сверяет точные ID с независимой фикстурой; дополнительно сохраняются 12
выборок DOM через rAF (с таймером 100 мс при отсутствии кадра). Проверяются края маски; это не видео
и не измерение производительности физического устройства.

Проверка обязана падать, если убрать фильтр выбранной даты. Для проверки самого
сторожа: `ISKRA_CALENDAR_MUTANT=1 npm run check:calendar-browser` — ожидается
ошибка несовпадения данных, а не успешное завершение.

CI: обязательный `.github/workflows/ci.yml` запускает календарь вместе с геометрией шапки и сохраняет
артефакты даже при ошибке. Локальные доказательства по умолчанию лежат в
`/tmp/iskra-calendar-day-qa`; путь меняется через ISKRA_QA_OUTPUT.

Дополнительный отрицательный контроль краткой подмены:
`ISKRA_CALENDAR_TRANSIENT_MUTANT=1 npm run check:calendar-browser` должен упасть,
даже если после двух кадров правильные ID восстановлены.
Сквозная проверка с локальными синтетическими аккаунтами и БД:
`ISKRA_QA_BASE_URL=http://127.0.0.1:5316 node scripts/security/checkLocalCalendarDay.mjs`.
